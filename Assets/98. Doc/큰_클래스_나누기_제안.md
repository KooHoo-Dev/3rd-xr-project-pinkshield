> 2026-11-18 밤 작성 (사용자 이동 중 Claude 검토). **아직 코드는 바꾸지 않았습니다.** CLAUDE.md 규칙("300줄 넘는 클래스를 고칠 때는 먼저 나눌지 물어볼 것")에 따라 결정은 사용자가 합니다.
> 원칙은 [AI-005](../../DevLog/ai-collab/AI-005-AI-설계가-만드는-거대-클래스와-예방-규칙.md), 본보기는 오늘 나눈 `CardRevealer`(863 → 415줄, 부품 7개 + 순수 `CounterPile`).

## 0. 공통 사항

- **씬 값은 모두 코드 기본값과 같습니다.** `Shop.unity` 확인: `reactionSeconds 1.6`, `angrySeconds 1.8`, `sidewalkZ 6.4`, `maskHeadOffset 0.09`, `droppedPackHeight 0.008`, `tabSelectedText (1, 0.85, 0.3)`, `flySeconds 0.35`, `arrivalFlashDelay 2.6`. 숫자 값을 부품의 `Settings` 묶음으로 옮겨도 잃는 값이 없습니다.
- **연결(참조) 필드는 그대로 둡니다.** 빌더(`CustomerFloorBuilder` · `ThiefBuilder` · `BinderBuilder`)와 `SceneSetupTests`가 필드 이름으로 넣고 확인합니다. 중첩 묶음 안으로 옮기면 경로가 바뀌어 연결이 끊깁니다(`FormerlySerializedAs`도 중첩 안으로는 동작하지 않음).
- **빌더 한 줄은 같이 고쳐야 합니다:** `ThiefBuilder.cs` 42줄 `FindProperty("sidewalkZ")`.
- **손님과 도둑의 등장 타이머가 같은 코드입니다** (손님 135–143줄, 도둑 148–156줄: 일정표 + 흐른 시간 + 다음 번호) → 순수 클래스 `SpawnClock` 하나로.

## 1. ThiefDirector (369줄) — 나눔, 1순위

리뷰에서 "팩 상태 플래그(`carrying` · `packDropped` · `stolenToday` · `returningPack`)에 테스트 없음"으로 지적된 곳입니다.

| 부품 | 맡는 일 | 줄 수 | 생성자로 받는 것 |
|---|---|---|---|
| `FreePackState` (순수 C#) | 플래그 세 개를 상태 하나로: `Home / Carried / Dropped / Stolen` | ~50 | 없음 |
| `FreePackHolder` | 팩 제자리 기억 · 진열 켜고 끄기 · 손에 붙이기 · 바닥에 놓기 · 제자리 놓기 · `returningPack` 재진입 막기 | ~75 | `HeldItem`, 진열 오브젝트, `Settings { droppedPackHeight }` |
| `ThiefBody` | 키 재기 · 복면 씌우기 · 손 뼈 찾기 | ~40 | 복면 템플릿, `Settings { maskHeadOffset }` |
| `SpawnClock` (순수, 공용) | 일정표대로 등장할 때가 됐는지 | ~30 | `float[] schedule` |

**테스트 (`FreePackStateTests`)**: 하루 시작 = 제자리 · 도둑 등장 가능 / 훔치면 운반 중 · 등장 불가 / 운반 중 잡힘 → 바닥 / 훔치기 전 잡힘 → 떨어뜨림 없음 / 바닥 팩 줍기 → 제자리 / 제자리 팩 줍기 → 무시 / 운반 중 도망 → 도난 / 도난 뒤 퇴장 → 제자리 숨김 / 강제 종료(운반 중 → 도난 아님, 바닥 → 되찾음) / 도난 다음 날 → 제자리.
`returningPack`은 XRI 이벤트 재진입 방지라 EditMode로 못 보므로 Play 확인 목록에.

**결과 · 위험**: 남는 Director 약 250줄. 테스트를 먼저 쓰고 옮길 수 있어 **위험 낮음~중간**.

## 2. CustomerDirector (436줄) — 나눔, 2순위 → ✅ 11-19 완료 (276줄)

> 실제로 나눈 것: `CustomerBodyFactory` · `QueueMover` · `PatienceRules`(+테스트) · `SpawnClock` 재사용 · 제안에 없던 `CheckoutLine`(계산대 줄 흐름, 300줄 규칙 때문에 추가) · 손님 동선 개편용 `BrowseArea`. `BrowseSpotPicker`는 `BrowseArea` 안으로 들어감.


| 부품 | 맡는 일 | 줄 수 | 생성자로 받는 것 |
|---|---|---|---|
| `SpawnClock` (공용) | 등장 시각 | 위와 같음 | `float[]` |
| `PatienceRules` (순수 static) | 인내 시간 = 기본 + 추가 × max(0, 물건 수 − 1), 지금 비율이 `None / Waiting / Impatient / Expired` 중 무엇인지 | ~35 | 없음 |
| `BrowseSpotPicker` (순수 static) | 빈 구경 자리 고르기 (없으면 -1) | ~15 | 없음 |
| `CustomerBodyFactory` | 손님 몸 만들기(외형 · 애니메이터 · 키 · 말풍선) | ~50 | 로스터 · 피커 · 시작 위치 · 부모 · 글꼴 · `Func<bool> isPaused` · 난수 |
| `QueueMover` | 줄 합류 · 도착 · 당기기 · 칸 위치 · 떠나는 길 | ~90 | `CustomerLine<CustomerAgent>`, 줄 칸들, 통로, 맨 앞 도착 콜백 |

**먼저 바꿀 연결**: `CustomerAgent.Init`(76줄)이 `CustomerDirector`를 통째로 받지만 쓰는 것은 117줄 `IsPaused` 하나 → `Func<bool> isPaused`로. 그러면 공장 부품이 Director를 몰라도 되고, 도둑도 같은 공장을 씁니다.

**테스트**: `PatienceRules`(물건 3개 → 추가 2번, 계산대 아니면 기본만, 재촉 비율 넘음, 이미 말한 대사 다시 안 함, 시간 초과) · `BrowseSpotPicker`(다 참 → -1, 찬 자리 건너뜀) · `SpawnClock`(첫 시각 전 false, 두 시각 지나면 두 번, 멈추면 대기 없음).

**결과 · 위험**: 남는 Director 약 270줄. 줄 규칙은 11-18 기기 피드백으로 고친 곳이라 **위험 중간** → `QueueMover`는 맨 마지막에 따로 커밋.

## 3. BinderView (397줄) — 나눔, 3순위 (얻는 것은 중간)

| 부품 | 맡는 일 | 줄 수 |
|---|---|---|
| `BinderCursor` (순수) | 탭 · 페이지 · 배치 두 개, 탭/페이지/카드 찾아가기(다른 탭 카드면 그 탭으로), 도감 번호 | ~70 |
| `StashedCards` (순수) | 보관 예정 카드 id (중복 없이 순서 유지) | ~25 |
| `BinderSocketStore` | 표지 소켓 잠금 · 한 프레임 뒤 선택 풀기 · 칸으로 날리기 | ~60 |
| `BinderTabBar` | 탭 버튼 연결 · ★ / 색 / 굵기 표시 | ~40 |

**테스트 (`BinderCursorTests`)**: 탭 바꾸면 0쪽 / 마지막 쪽 넘으면 고정 / 다른 탭 카드 찾으면 속성 탭으로 / 모르는 카드면 탭 유지 / 불 탭에서도 전체 도감 번호 / 같은 id 한 번만 / 마지막에 넣은 카드.
**결과 · 위험**: 남는 View 약 200줄, **위험 낮음**. 다만 핵심 규칙(`BinderLayout` · `BinderTabs`)은 이미 테스트가 있어 새로 얻는 것은 앞의 둘보다 적습니다.

## 4. 에디터 도구

- **ShopSceneBuilder (574줄) — 가볍게, 급하지 않음.** 집 만들기(408–512줄)와 메뉴 · 디버그 패널(351–407, 513–574줄)만 `HomeBuilder` · `MenuBuilder`로 옮기면 약 350줄, 이미 있는 구역별 빌더 방식과 같음. 집이나 메뉴를 다음에 고칠 때 같이.
- **InteriorBuilder (562줄) — 그대로.** 네 프리팹의 "처음 배치"만 만들고 이후는 손으로 다듬는 원칙이라 다시 실행이 드묾. 나눠도 테스트가 생기지 않아 "줄이려고만 나누지 않는다"(AI-005)에 해당.
- **CardPrefabBuilder (467줄) — 한 부분만.** 미리보기 이미지 찍기(371–467줄)는 바뀌는 이유가 달라 `CardPreviewRenderer`로 떼면 약 370줄. 나머지는 한 파이프라인이라 그대로.

## 5. 추천 순서

1. `SpawnClock` + `FreePackState` + 테스트 → ThiefDirector 적용
2. `PatienceRules` · `BrowseSpotPicker` + 테스트 → `CustomerAgent.Init` 바꾸기 → `CustomerBodyFactory` → (따로 커밋) `QueueMover`
3. `BinderCursor` → `BinderSocketStore` → `BinderTabBar`
4. 에디터 도구는 해당 파일을 다음에 고칠 때

단계마다 EditMode 테스트 · Build Shop Scene, Play 확인 항목은 [리팩토링 Play 확인 목록](../../DevLog/리팩토링_Play_확인목록.md)에 이어서 추가합니다(도둑 잡기 · 놓치기, 줄 서기, 바인더 소켓).
