# 카드팩 개봉 연출 설계 — 모바일 포켓몬 카드 게임(Pocket) 분석과 VR 적용

> 작성 2026-11-16 · 대상: 3일차 "개봉 연출·사운드·햅틱" (설계서 v1 7-2, 기획서 5-2)
> 레퍼런스: Pocket의 팩 개봉 화면 (기획서 레퍼런스 (1)). 세부 연출은 실제 플레이 영상으로 한 번 더 확인할 것 — 아래 "확인 필요" 표시.

## 1. Pocket 개봉 흐름 분석

Pocket의 개봉은 **"고르기 → 자르기 → 한 장씩 넘기기 → 모아 보기"** 4단계이고, 단계마다 손가락 동작이 하나씩 있습니다.

| 단계 | 화면에서 일어나는 일 | 플레이어 동작 | 이 단계가 만드는 감정 |
|---|---|---|---|
| ① 고르기 | 여러 팩 중 하나를 고름 | 넘겨 보고 탭 | "이 팩이 좋을 것 같아" (운을 내가 고른 느낌) |
| ② 자르기 | 팩 윗부분에 자르는 선이 보이고, 손가락으로 그으면 잘림 | 가로로 긋기 | 기대감이 올라가는 짧은 준비 동작. 너무 빨리 끝나지 않음 |
| ③ 넘기기 | 카드가 묶음으로 나오고, 맨 앞 카드를 밀어 치우면 다음 카드가 보임 | 한 장씩 밀기 | 한 장마다 작은 긴장. 뒤로 갈수록 좋은 카드가 나올 확률이 높음 |
| ④ 모아 보기 | 5장을 한 화면에 모아 보여주고 새 카드 표시 | 확인 | 결과 정리, "새 카드" 뿌듯함 |

### 연출에서 배울 점

1. **동작 하나에 반응 하나.** 긋기·밀기마다 소리와 진동이 즉시 따라옵니다. 기다리는 시간이 아니라 "내가 하는 시간"으로 느껴집니다.
2. **좋은 카드일수록 공개가 느려집니다.** 일반 카드는 바로 넘어가고, 희귀 카드는 반짝임·멈춤이 들어갑니다. 연출 길이 자체가 등급 신호입니다.
3. **마지막 카드가 클라이맥스.** 뒤 슬롯일수록 좋은 등급 확률이 높아서, 확률 구조와 연출 순서가 맞물립니다. (우리 기획의 "5번째 = 히트 슬롯"과 같음)
4. **특수 팩은 열기 전에 미리 알려 줍니다.** 일반 팩과 다른 연출로 "뭔가 다르다"를 먼저 보여 주고 결과로 확인시킵니다. _확인 필요: 정확한 형태_
5. **반복에 지치지 않게.** 빨리 넘기면 연출이 짧아지고, 요약 화면에서 한 번에 정리됩니다.

## 2. VR로 옮기기 — 단계별 대응

| Pocket | 우리 게임 (VR) | 현재 상태 |
|---|---|---|
| ① 팩 고르기 | 선반에서 팩 집기 + 단서(윗면 접힘, 뒷면 뒤집힘) + 직접 뒤집어 표시 | ✅ 2일차 구현 (DEC-001) |
| ② 손가락으로 긋기 | **왼손 그립으로 잡으면 팩이 눈앞(정면 35cm, 월드 고정)에 뜨고, 오른손 트리거를 누른 채 윗부분 가이드 선을 따라 가로로 긋기** (TearGestureOpen). 그은 만큼 노란 선이 채워지고 10%마다 진동, 너비 70% 자르면 개봉 | ✅ 1차 구현 (2026-11-16, 실기기 확인 전) |
| ③ 묶음에서 한 장씩 밀기 | 자르면 팩이 있던 자리(눈앞)에 카드 5장이 **앞면 묶음**으로 나옴. **오른손 트리거**를 누를 때마다 맨 앞 카드가 카운터로 포물선을 그리며 날아가 펼쳐지고 다음 카드가 보임. 묶음에 있는 동안은 잡을 수 없고, 카운터에 놓인 뒤 잡을 수 있음 | ✅ 1차 구현 (2026-11-16) |
| ③-희귀 연출 | 등급별 연출 예산(아래 3장). 5번째 카드는 넘기기 전에 뒷면에서 등급 색 빛이 샘 | 멈춤·진동만 1차 적용 (빛·소리·파티클 없음) |
| ④ 모아 보기 | 카운터 위 5장 + 새 카드 배지. 이 자리에서 바인더/판매 진열대로 바로 꽂음 | 펼침 · NEW 배지 있음 |
| 특수 팩 예고 | 갓팩·레전더리 확정 팩: 찢는 순간 팩 틈에서 금색 빛 + 다른 효과음 | 없음 |
| 빨리 넘기기 | 연출 중 트리거 길게 누르면 남은 카드 즉시 공개 | 없음 |
| (Pocket에 없음) 10팩 상자 | Poke 버튼 → 결과판에 팩이 한 줄씩 쌓임(1/10…10/10) → 합계 → 좋은 카드 5장 펼침 | ✅ 오늘 1차 구현 (결과판) |

## 3. 등급별 연출 예산

연출 길이를 등급 신호로 씁니다. 값은 `RarityRevealProfile`(ScriptableObject)로 빼서 조정합니다.

| 등급 | 뒤집기 시간 | 멈춤 | 빛 | 소리 | 햅틱(세기/길이) |
|---|---|---|---|---|---|
| 노말 | 0.2초 | 없음 | 없음 | 종이 넘김 | 0.1 / 0.03초 |
| 레어 | 0.25초 | 없음 | 테두리 반짝 | 맑은 '띵' | 0.2 / 0.05초 |
| 수퍼레어 | 0.4초 | 0.2초 | 홀로그램 | 반짝 효과음 | 0.4 / 0.1초 |
| 유니크 | 0.5초 | 0.4초 (뒷면 빛샘 먼저) | 글로우 | 상승음 | 0.6 / 0.15초 ×2 |
| 레전더리 | 0.8초 | 0.8초 (빛샘 → 정지 → 공개) | 강한 글로우 + 파티클 소량 | 전용 징글 | 1.0 / 0.3초 |

- 한 팩 기준 연출 총합은 일반적으로 **4초 안**, 레전더리가 있어도 **7초 안**. 7일간 약 72팩을 열기 때문에(기획서) 길면 지칩니다.
- Quest 성능: 파티클은 레전더리만, 한 번만 재생(루프 금지).

## 4. 코드 구조 제안

```text
IPackOpenMethod (ActivatePackOpen / TearGestureOpen)
   └► PackOpener.TryOpen ── 규칙(PackOpeningService) ──► PackResult
                                   └► PackRevealSequence  (새로 만듦, 상태 머신)
                                         Emerging → Revealing(0..4) → Summary → Done
                                         ├ RarityRevealProfile (등급별 시간·소리·햅틱)
                                         ├ CardRevealer (카드 풀, 카운터 펼침) ← 지금 것 재사용
                                         └ CardRevealed 이벤트 → 사운드·햅틱·새 카드 배지
```

- **판정은 지금처럼 개봉 시점**(찢기 완료 순간)에 한 번만. 연출은 결과를 "보여주기"만 하므로 연출을 건너뛰어도 데이터는 같습니다. → 빨리 넘기기·중간에 페이즈가 바뀌어도 안전.
- `PackRevealSequence`는 진행 중 상태를 하나만 가짐. 연출 중 다른 팩 개봉 요청은 무시(또는 현재 연출을 즉시 끝내고 시작).
- **TearGestureOpen 세부** (확정: 그립으로 집기 유지, 왼손 들기·오른손 자르기 고정, 눈앞 월드 고정)
  - 왼손 그립 선택 시 `trackPosition/trackRotation`을 꺼서 XRI가 팩을 손으로 끌고 가지 않게 하고, 잡은 순간 시선의 수평 정면 35cm·8cm 아래에 앞면이 플레이어를 향하게 둡니다. 왼손 그립을 놓으면 원래대로(진행도 초기화) → 3초 뒤 선반 복귀는 기존 그대로.
  - 오른손은 팩을 선택하지 않습니다. 오른손 인터랙터(근접·원거리 겸용 우선)의 `activateInput`(트리거)과 위치만 읽어서, 팩 로컬 좌표로 바꾼 뒤 자르는 선 근처(위아래 4cm, 앞뒤 8cm)에 있을 때의 X 범위를 넓혀 갑니다. 그래서 두 손이 팩을 "뺏어 잡는" 문제가 생기지 않습니다.
  - 진행도 = 자른 X 범위 / 팩 너비. 끊어 그어도 이어짐. 10%마다 오른손 진동(자를수록 조금 세짐), 70%면 개봉 요청. 거부되면(영업 중 등) 진행도만 초기화.
  - 가이드 선(흰색)·자른 선(노란색)은 팩 머티리얼을 빌려 색만 바꿉니다(런타임에 셰이더를 찾으면 빌드에서 빠질 수 있음).
  - 남은 것: 찢는 소리, 윗부분이 떨어져 나가는 연출, 오른손잡이·왼손잡이 설정.
  - 자르기가 어려우면 프리팹에서 `ActivatePackOpen`으로 바꾸기만 하면 됨(설계서 7-2 그대로).
- **햅틱**: 상호작용 중인 손의 `XRBaseInputInteractor.SendHapticImpulse(세기, 시간)`. 이벤트 인자의 `interactorObject`에서 꺼냅니다.

## 5. 보완 검토 (현재 설계·구현에서 빠진 것)

| # | 문제 | 영향 | 보완 |
|---|---|---|---|
| 1 | **개봉 실패 피드백이 디버그 패널 글자뿐** (영업 중 트리거, 재화 부족) | 이번 빌드처럼 "아무 반응 없음"으로 보여 버그와 구분이 안 됨 | ✅ 구현: 팩 위(상자는 카운터 위)에 말풍선 `WorldToast` + 팩을 든 손에 거부 진동 2회. 개봉 성공 시 진동 1회 |
| 2 | 카드가 카운터에 바로 깔림 | Pocket의 핵심인 "한 장씩 넘기는 긴장"이 없음 | 2장 ③ 묶음 → 한 장씩 넘기기 |
| 3 | 묶음이 나오는 위치 | 머리에 붙이면(Head-locked) 멀미 | 팩을 든 손 앞, **월드 고정**. 시작 위치만 머리 정면 0.4m 근처로 보정 |
| 4 | 5번째 빛샘이 결과를 미리 알려 줌 | 의도된 기대감이지만, 판정이 빛샘 뒤에 일어나면 어긋남 | 판정을 개봉 시점에 한 번만 (현재 구조 유지) → 문제 없음. 테스트로 고정 |
| 5 | 상자 50장 요약 화면 없음 | 무엇을 얻었는지 다 못 봄 | 오늘은 결과판(팩별 최고 등급·새 카드 수·특수 팩) → 3일차에 50장 격자 요약(Ray UI) |
| 6 | 상자 연출 중 상자 버튼 다시 누름 | 결과판이 덮어써짐 (재화는 정상 차감) | ✅ 구현: 결과판이 채워지는 동안 상자·단일 팩 개봉을 막고 "상자를 여는 중이에요." 안내 (재화 차감 전에 막음) |
| 7 | 연출 반복 피로 | 72팩 × 긴 연출 | 빨리 넘기기, 노말 연출 최소화 |
| 8 | 새 카드 배지 | 데이터(`IsNew`)는 있는데 표시 없음 | ✅ 구현: 카드 오른쪽 위 "NEW" 배지(TMP, Visual 아래라 함께 뒤집힘) |

## 결정 필요

- [잠정] 묶음에서 카드 넘기기 방식: **오른손 트리거로 넘기기**로 1차 구현 (자르기와 같은 손·같은 버튼이라 흐름이 이어짐). 집어 빼기(Grab)는 실기기에서 비교 후 결정.
- [잠정] 단일 팩 카드: **앞면 묶음(Pocket식)** 으로 1차 구현. 뒷면으로 내고 한 장씩 뒤집는 방식은 "5번째 빛샘"과 함께 다시 검토.
