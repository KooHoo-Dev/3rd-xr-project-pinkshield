# 집 업그레이드 설계 (E1 방 진열장 · E2 방 업그레이드 · E3 경제) — 초안 11-19

> 상태: **결정 완료(11-19, DEC-031) — 구현 전**. 돈은 달러, 배율 없음(B2 결정).

## 0. 왜 필요한가 (피드백)
- 9장 "집으로 돌아와 카드 팔고 나면 할 게 없다 — 집 업그레이드, 가구 구매 혹은 커뮤니티 확인이 더 추가되면 좋을 것 같음"
- 5-6 "바인더 UI에서 직접 카드를 집고 보관하는 경험이 없어서 모으는 경험을 잘 못 느낌"
- 7-2 "카드팩만 사는 건 충분히 쓸 수 있음. 다른 물품을 사게 된다면 고려해 봐야 함"
- 7-6 한 판 더? → 보류

## 1. 지금 구조에서 확인한 사실 (코드)
| 항목 | 지금 | 이 설계에 주는 영향 |
|---|---|---|
| 최종 점수 (`ScoreRules`) | 현금 + **보유 카드 전체 × 기준가** + 수집 종류 × 10 | 진열한 카드도 이미 "보유 카드"라 점수에 들어감 → 진열 점수를 따로 주면 **이중 계산** |
| 등급 기준가 (`RarityTable`) | 노멀 1 · 레어 5 · 수퍼레어 20 · 유니크 100 · 레전더리(5번째 값, 확인 필요) | 팔기 vs 모으기: 팔면 인기 속성 ×1.5 − 수수료 10%, 모으면 기준가 그대로 점수 |
| 랭크 (`ScoreConfig`) | S 4000 · A 3400 · B 2400 · C 0 | 업그레이드로 현금이 줄면 점수가 깎임 → "자산" 처리 필요 |
| 경제 (`EconomyConfig`) | 팩 $10 · 상자 $90 · 일당 $40 · 청소 +$5 · 빠른 계산 +$2 · 시작 $0 · 판매 등록 4칸 · 즉시 판매 60% | |
| 집 화면 | `HomePanel` 상속(판매 · 커뮤니티 화면), 바인더 `BinderView` | 상점 화면은 `HomePanel`을 상속하면 됨 |
| 보유 카드 | `Collection` (카드 id → 장수) | 진열은 "보유 중 일부를 진열로 표시"만 하면 됨 |

### 대략 수입 (A9 손님 상향 뒤, 추정 — Play로 확인 필요)
- 일당 $40 × 7 = $280
- 청소 하루 2~3곳 × $5 × 7 ≈ $90 (F1 확률 생성 기준)
- 빠른 계산 손님 45명쯤 × 절반 × $2 ≈ $45
- 카드 판매 ≈ $200 (기획서 시뮬레이션)
- **합계 약 $600** (기획서 시뮬레이션 수치는 손님 상향 전 값이라 다시 재야 함)

## 2. E1 방 진열장 — "모으는 손맛"
- 바인더 카드 칸에 **[진열]** 버튼 → 방 책장(`Library`, 3-2 평면도 왼쪽 벽) 진열 칸에 카드가 **스탠드에 세워진 실물**로 놓임. 손으로 꺼내 볼 수 있고, 놓으면 제자리로.
- 진열 칸 수: 처음 3칸, 업그레이드(E2)로 6 · 10칸. 진열한 카드는 팔 수 없음(판매 등록과 같은 규칙, 바인더 칸에 "진열 중").
- 점수: **따로 주지 않음** (이미 보유 카드 값으로 들어감, 1장 참고). 대신 최종 판에 "진열장" 줄로 진열 카드 그림을 보여 줌 — `[결정 필요] Q4`
- 코드: `ShowcaseRules`(순수: 진열 가능 여부 · 칸 수, 테스트) · 세션에 진열 목록(`GameSession.Showcase`) · `ShowcaseShelf`(책장 칸에 카드 세우기, 카드 오브젝트는 `CardRevealPool` 방식 재사용) · 바인더 칸 버튼 1개.

## 3. E2 방 업그레이드 — "돈이 방에 남는다"
**어디서 사나**: 방 컴퓨터 화면에 "슬라임마켓" 탭(커뮤니티 화면 옆). `[결정 필요] Q3` 산 물건은 **다음 날 아침 방에 택배 상자**로 도착 → 잡아서 열면 가구가 바뀜 / 또는 사자마자 바뀜.

**목록 (달러)** — 팩 $10 기준, Lv2 하나 ≈ 팩 6~7개. `[결정 필요] Q5`
| 분야 | Lv1 (처음) | Lv2 | Lv3 | 효과 |
|---|---|---|---|---|
| 진열장 | 3칸 | $40 → 6칸 | $100 → 10칸 + 조명 | E1 칸 수 |
| 바인더 | 기본 | $60 → 판매 등록 4 → 6칸 | $140 → 금박 바인더 UI · 즉시 판매 60 → 70% | 판매 |
| 컴퓨터 | 내일 인기 속성 | $70 → **모레** 인기 속성 | $150 → 카드 시세표(카드별 오늘 · 내일 값) | 판매 타이밍 정보 |
| 침대 | 기본 | $70 → 다음 날 손님 인내심 +10% | $130 → +20% & 아침 무료 팩 1개 | 영업 |
| 꾸미기 (포스터 · 러그 · 조명 · 피규어) | — | 각 $15~30 | — | 효과 없음, 방 꾸미기 |
- 전체 약 $900+ vs 수입 약 $600 → **다 살 수 없어 고르게 됨**.

**점수**: 랭크 점수에 "가구 값" 줄 추가 — 산 가격의 몇 %를 자산으로 칠지 `[결정 필요] Q2`. 100%면 "돈을 쓴 게 아니라 자산을 바꾼 것"(FIX 설계 B2 제안). 팩은 기대 카드 값이 팩 값보다 높아서(기획서 시뮬레이션: 72팩 → 카드 값이 점수 대부분) 점수만 보면 여전히 팩이 유리 → 업그레이드는 효과 · 재미로 고르는 쪽.
**엔딩 문구**: 자산 규모에 따라 한 줄(예: "원룸 카드 부자") — 기존 정직원 / 계약 연장 문구 뒤에 붙임.

**코드 구조** (새 클래스 위주, AI-005)
| 클래스 | 하는 일 |
|---|---|
| `UpgradeCatalog` (SO) | 분야 · 단계 · 가격 · 효과 값 |
| `UpgradeRules` (순수) | 살 수 있나 · 다음 단계 · 효과 계산 · 가구 자산 값 (EditMode 테스트) |
| `GameSession.Upgrades` | 산 단계 목록 (분야 → 단계) |
| `MarketScreen` (`HomePanel` 상속) | 슬라임마켓 화면 · 사기 버튼 |
| `RoomUpgradeView` | 방 가구 모델 바꾸기 (LowPolyInterior 에셋에서 고름) |
| `DeliveryBox` | (Q3에서 택배를 고르면) 아침 택배 상자 |
| 효과 연결 | 판매 칸 수 · 즉시 판매율 → `EconomyRules`에 단계 값 넘김, 인내심 → `PatienceRules`, 인기 속성 미리 보기 → `CommunityScreen` |

## 4. E3 경제 숫자 맞추기
- 업그레이드가 들어간 뒤 7일 한 판의 수입 · 지출 · 점수를 다시 재고, 랭크 기준(2400 / 3400 / 4000)을 조정.
- 방법: 기획서 5-5처럼 순수 C# 시뮬레이션(EditMode 테스트 형태, 수천 회) + 실제 한 판 기록 비교.

## 5. 구현 순서 (제안)
1. E1 진열장 (가장 작고, "모으는 손맛" 피드백에 직접 답함) — 중
2. E2 상점 화면 + 진열장 · 바인더 업그레이드 2개만 먼저 — 중
3. E2 나머지 분야 + 택배 상자 — 중~대
4. E3 시뮬레이션 · 랭크 조정 — 중
