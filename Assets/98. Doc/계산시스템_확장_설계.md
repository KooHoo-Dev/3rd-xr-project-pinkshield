# 계산 시스템 확장 설계 (2026-11-18, Quest 기기 테스트 피드백)

> 입력: 사용자 기기 테스트 피드백 "계산 시스템 디테일 추가"
> 1) 손님이 카드팩 하나만이 아니라 **피규어 · 카드팩 상자**도 산다
> 2) 바코드를 다 찍으면 **포스기에서 가격 확인 → 가격 입력 → 결제 버튼**
> (보완) 가격 입력이 너무 복잡하면 **산 물건을 집어서 열린 종이봉투에 담아 준다**
>
> 근거 코드: `CustomerDirector`(줄 · 결제) · `ScannableItem` · `BarcodeScanner` · `SalesRules`(PickPurchase · CompleteSale) · `CustomerFloorBuilder` · `CustomerItemBuilder` · `EconomyConfig` · `CampaignConfig`
> 상태: K1~K6 **추천안으로 확정**(2026-11-18). 1~6단계 구현함(7 키패드는 선택) — 10장 "구현 현황"

---

## 1. 지금 계산 흐름과 한계

```
손님 줄 맨 앞 도착 → PrepareCheckout: 물건 1개를 카운터(itemSpot)에 생성
  ├ 진열 카드를 사기로 했으면 그 카드 (SalesRules.PickPurchase)
  └ 아니면 "카드팩 (가게 재고)"
→ 플레이어가 스캐너를 잡고 트리거로 찍음 → 이름 · 가격 표시
→ 결제 버튼(Poke) → ServeFront: 진열 카드면 장부 기록, 손님 퇴장
```

| 한계 | 왜 문제인가 |
|---|---|
| 물건이 늘 **1개** | 찍기 → 버튼 한 번으로 끝나 반복 작업이 금방 지루함 (피드백의 출발점) |
| 가게 재고 판매는 **플레이어 수입 0** | 재고를 팔아도 플레이어에게 아무 변화가 없음 → 물건 종류를 늘려도 "귀찮은 일"만 늘 수 있음 (3장) |
| 물건은 **잡을 수 없음** (콜라이더만, `CustomerItemBuilder`) | 봉투 담기를 하려면 잡기가 필요 |
| 결제 확인은 "찍었는가"만 | 가격 입력 · 봉투 같은 손동작을 넣을 자리가 없음 |
| 계산 코드가 `CustomerDirector` 안에 섞여 있음 (366줄) | 물건이 여러 개가 되면 줄 관리와 계산이 더 엉킴 → 계산대를 따로 떼는 게 좋음 (6장) |

## 2. 목표 흐름 (추천안)

```
① 손님이 장바구니(1~4개)를 카운터에 올림
② 플레이어가 하나씩 바코드를 찍음 → 포스기 화면에 품목이 한 줄씩 쌓이고 합계가 자동 계산
③ 찍은 물건을 집어 열린 종이봉투에 넣음 (안 찍은 물건은 봉투가 튕겨 냄)
④ 다 담기면 포스기 [결제] 버튼이 켜짐 → 누르면 손님이 봉투를 들고 감
```

사용자 원안(가격 직접 입력)과 보완안(봉투)을 비교하면:

| 안 | 흐름 | 장점 | 단점 |
|---|---|---|---|
| **A. 가격 직접 입력** | 찍기 → 합계를 보고 키패드로 숫자 입력 → 결제 | "포스기를 다루는" 실감, 틀리면 손님 반응 등 실수 거리가 생김 | VR 키패드는 **누르기가 느리고 잘못 눌리기 쉬움**(C2: 버튼 간격 문제를 이미 겪음). 화면의 숫자를 다시 치는 일이라 머리는 안 쓰고 손만 바쁨 |
| **B. 합계 자동 + 봉투 담기** ⭐추천 | 찍기 → 봉투에 담기 → 결제 버튼 | 물건을 **집고 넣는 손동작**이 VR에 맞음. 물건이 여러 개일수록 자연스럽게 일이 늘어남 | 숫자 실수 같은 "긴장"은 없음 (4장의 실수 처리로 보완) |
| **C. 받은 돈 + 거스름돈 입력** | 찍기 → 손님이 지폐를 냄 → 거스름돈 입력 | 계산 게임다운 머리 쓰기 | A의 키패드 문제 + 돈 오브젝트까지 필요, 가장 큼 |

**추천: B를 기본으로, A는 나중에 "바쁜 날(후반 일차) 난이도"나 옵션으로.** 이유:
- 피드백이 원하는 "계산 디테일"의 핵심은 **할 일이 늘고 손이 바빠지는 것**으로 읽힘. 봉투 담기는 그걸 VR답게 채움.
- A안의 키패드는 B 위에 그대로 얹을 수 있게 설계함(5-3). B를 먼저 만들어도 버리는 코드가 없음.

## 3. 보상과 벌칙 — "계산을 잘하면 무엇이 좋은가"

지금은 가게 재고를 팔아도 플레이어 돈은 그대로입니다(판매 등록 카드만 수입). 피규어 · 상자를 추가해도 같은 구조면 계산은 **보상 없는 노동**이 됩니다.
알바생 설정에 맞는 선택지:

| 안 | 내용 | 비고 |
|---|---|---|
| a. 손님 팁 | 빨리(예: 줄 맨 앞 도착 후 N초 안) 끝내면 1~3 팁 | 즉시 보상, 숫자가 작아 경제 균형을 덜 흔듦 |
| b. 사장님 평가 → 알바비 보너스 | 하루 계산 정확도 · 속도를 모아 정산 때 `dailyBasePay`에 가감 | 기존 정산(청소 보너스 · 감점)과 같은 방식이라 자연스러움 |
| c. 보상 없음, 실수만 감점 | 틀리면 알바비 차감 | 단순하지만 "하기 싫은 일"이 됨 |

추천: **b**(청소처럼 정산에 반영) — 이미 `cleanupBonus` · `cleanupPenalty`가 있어 같은 자리에 `checkoutBonus` · `checkoutPenalty`를 두면 됩니다. 원하면 a를 함께.

## 4. 실수 처리

| 상황 | 추천 처리 |
|---|---|
| 안 찍은 물건을 봉투에 넣음 | 봉투가 튕겨 냄 + 안내 "먼저 바코드를 찍어 주세요" (지금 결제 버튼 안내와 같은 방식) |
| 같은 물건을 두 번 찍음 | 무시 (지금 `ScannableItem.TryScan`이 이미 한 번만 받음) |
| 물건을 바닥에 떨어뜨림 | 잠시 뒤 카운터 제자리로 돌아옴 (`BarcodeScanner`의 "놓으면 돌아옴"과 같게) |
| 다 담기 전에 결제 버튼 | 안내 "아직 봉투에 안 담은 물건이 있어요" |
| 오래 걸려 손님이 떠남 | 지금처럼 판매 없음. 물건이 많을수록 기다려 주는 시간을 늘림 (`인내 = 기본 30초 + 물건당 N초`) |

A안(가격 입력)을 넣을 경우: 틀린 금액 → 손님 "어? 금액이 이상한데요" 제스처 + 다시 입력. 두 번 틀리면 감점.

## 5. 물건 · 데이터

### 5-1. 품목 (수치는 SO에)

| 품목 | 가격(안) | 모양 | 비고 |
|---|---|---|---|
| 카드팩 | 10 (`packPrice`) | 기존 `CustomerItem_Pack` | |
| 카드팩 상자 | 90 (`boxPrice`) | 상자 (팩 상자 모델 재사용) | 크고 무거워 보이게, 봉투에 1개만 들어가게 해도 재미있음 |
| 피규어 | 30~60 | **[결정 필요]** 5-2 | |
| 판매 등록 카드 | 등록가 | 기존 `CustomerItem_Card` | 손님당 최대 1장. 지금 규칙(`SalesRules.PickPurchase`) 그대로, 플레이어 수입 |

새 SO `ShopItemConfig`(품목 목록: id · 이름 · 가격 · 프리팹 · 뽑힐 가중치 · 처음 나오는 일차) — "수치는 코드에 쓰지 않는다" 원칙(시스템설계서 1장).

### 5-2. 피규어 모양 — 새 에셋 없이

외부 에셋(LowPolyInterior · PolygonCity)에 피규어 · 장난감 모델이 없습니다. 두 가지 안:
- **(가) 아크릴 스탠드**: 이미 있는 슬라임 캐릭터 누끼 그림(`Char/<ID>_char.png`)을 투명 판 + 받침에 붙임. 카드 세계관과 바로 이어지고, 50종이 공짜로 생김 ⭐
- (나) 슬라임 피규어: 찌그러진 구 + 속성 색 + 눈. 입체감은 좋지만 종류가 적음

### 5-3. 장바구니 규칙 (순수 C#, EditMode 테스트)

`BasketRules.Roll(day, random)` → 품목 목록
- 개수 분포(안): 1개 50% · 2개 30% · 3개 15% · 4개 5%, 후반 일차일수록 많아지게 (`CampaignConfig.DayEntry`에 값)
- 판매 등록 카드: 지금처럼 `PickPurchase`로 0~1장을 먼저 정하고 나머지를 재고로 채움
- 합계 · "다 찍었나" · "다 담았나" 판정도 여기(로직/뷰 분리 원칙)

## 6. 코드 구조

```
CustomerDirector (줄 · 동선만)
   └ 맨 앞 손님 도착 → CheckoutCounter.Begin(agent, basket) / 끝나면 Completed 콜백

CheckoutCounter (새, 계산대 하나)          ← 지금 PrepareCheckout · ServeFront · ClearCheckout을 옮김
   ├ 물건 생성: 카운터 위 자리 4칸(itemSpots)
   ├ ScannableItem.Scanned → PosTerminal에 한 줄 추가
   ├ PaperBag.ItemBagged → 다 담기면 결제 버튼 켜기
   └ 결제 → SalesRules.CompleteSale(판매 등록 카드) + 계산 기록(3장 보상용)

PosTerminal (새, 뷰)   화면(월드 캔버스): 품목 · 가격 · 합계 · [결제]. A안이면 키패드(0~9 · ← · C)
PaperBag (새)          열린 봉투 + 안쪽 트리거. 찍은 물건을 놓으면 봉투 안으로 붙임(잡기 끔), 안 찍었으면 튕김
ScannableItem (수정)   잡을 수 있게(XRGrabInteractable, 평소 kinematic), 떨어뜨리면 제자리로
BasketRules (새, 로직) 장바구니 뽑기 · 합계 · 완료 판정 + 테스트
```

VR 쪽 주의:
- 봉투는 **물리로 쌓지 않음**. 물건을 트리거 안에서 놓으면 봉투 안 정해진 자리로 붙이고 잡기를 끔 → 튀어나오거나 떨림 없음
- 키패드(A안)를 만든다면 버튼 4cm 이상 · 간격 1.5cm 이상 (C2 교훈), 기존 `PokeButton` 재사용
- 포스기 위치: 결제 버튼 자리(카운터 왼쪽, x -0.35) 근처. 스캐너 · 물건 · 봉투 · 포스기가 한 팔 거리 안에 들어오게 배치
