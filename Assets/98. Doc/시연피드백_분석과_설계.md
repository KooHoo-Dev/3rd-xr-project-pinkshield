## 2. 내 제안 — 설계와 보완점

### A1. 개봉 중 카드가 작게 보임

**원인.** 카드는 실제 크기(6.3 × 8.8cm)입니다. 눈앞 팩은 35cm 거리라 세로 시야각이 약 14°, 넘긴 카드가 놓이는 카운터 한 줄은 거리 약 60cm에 간격 7.5cm라 약 8°밖에 안 됩니다. Quest에서는 작은 글자 · 그림이 뭉개집니다.

**"더 앞으로"만 하면 생기는 문제.** Quest 시각 편안함은 약 50cm 이상에서 좋고, 35cm는 이미 가깝습니다(눈 초점·수렴 불일치). 더 앞으로 당기면 피로합니다. → **거리는 조금 늘리고(35→45~50cm), 크기를 키웁니다.**

| | 지금 | 제안 |
|---|---|---|
| 개봉 중 팩 · 카드 묶음 | 35cm, ×1.0 → 14° | 45cm, ×1.5 → 약 16.5° |
| 카운터에 놓인 카드 | ×1.0, 간격 7.5cm | ×1.3, 겹쳐 쌓음 (B2) |

- 값은 `CardRevealer` / `TearGestureOpen`의 직렬화 필드(`presentScale`, `presentDistance`)로 뺍니다. 실기기에서 숫자만 고치면 됩니다.
- 보완: 팩 크기(`transform.localScale`)를 바꾸면 BoxCollider와 가이드선 · 자르기 판정 범위(위아래 4cm · 앞뒤 8cm)가 **같이 커지지 않으면** 판정이 어긋납니다. 판정 범위도 `lossyScale`로 곱해야 합니다. (지금은 레이 거리만 `lossyScale`을 곱함)
- 보완: 카드를 키우면 NEW 배지(A2) · 글자도 같이 커지므로 A2와 같이 확인.
- 선생님 제안 D1(지정 위치)이 이 값을 정의하는 자리가 되므로, 필드는 D1이 와도 그대로 쓰는 구조로 둡니다.

### A2. NEW 배지가 너무 큼

**원인.** `CardRevealView.CreateNewBadge`: 글자 크기 0.35, 띠(`<mark>`)가 글자 폭 + 좌우 여백까지 칠해져서 카드 폭의 약 40%를 가립니다.

**설계.** 글자 0.35 → **0.2** (약 55%), 위치는 카드 모서리에 더 걸쳐서 카드 그림은 가리지 않게 (카드 안쪽보다 바깥쪽 비중을 큼). 값은 상수 두 개(`NewBadgeFontSize`, `NewBadgeInset`)로 빼서 한 줄로 조정.
보완: 카드가 ×1.5로 커져도(A1) 배지 크기는 카드 비율로 따라가므로 같이 보고 조정.

### A3. 팩 접힘 — 거의 알아챌 수 없게 줄이기 (✅ 확정, 처음 해석이 반대였음)

사용자 답변: 지금은 윗부분이 **통째로 꺾여 있어 너무 쉽게 눈에 띈다.** 포켓몬 카드팩처럼 거의 알아채기 어려운 정도여야 한다. (참고 사진: 윗변의 압착 띠 + 그 아래 가로 줄)

**원인.** `PackPrefabBuilder`의 `FoldHinge`가 윗부분 2.2cm 판 전체를 55° 꺾어서 팩 실루엣 자체가 달라집니다 (`PackView.foldAngle = 55`).

**설계**

| | 지금 | 제안 |
|---|---|---|
| 접힘 각도 | 55° | **6~8°** (인스펙터 값, 실기기에서 조정) |
| 접히는 높이 | 2.2cm 판 전체 | **1.2cm** 압착 띠만 |
| 보이는 정도 | 정면에서도 바로 보임 | 정면에서는 거의 같고, 가까이서 옆으로 보거나 빛이 비칠 때만 "살짝 들뜸" |

- **모든 팩에 압착 띠 질감**(사진의 윗변 톱니·가로 줄)을 공통 디자인으로 넣습니다. 접힘 팩은 이 띠가 **아주 조금 들뜨거나 비뚤어진 것**뿐입니다. 이 띠가 곧 A4에서 뜯겨 나가는 윗부분이 되어 한 번에 해결됩니다.
- 확률은 그대로(접힘 20%, 확률 ×1.5, DEC-001). 뒤집힘 단서(5%)도 그대로.
- 보완: ① 각도가 너무 작으면 정말 안 보여서 "단서가 있다는 사실"을 아무도 모릅니다. 사용자 의도가 **"찾아낸 사람만 이득인 숨은 요소"** 라고 이해했는데 맞다면, 사장님 대사/튜토리얼에서 한 번 힌트를 줄지는 5일차에 결정. ② 값이 작아 z 겹침이 생기지 않는지 확인.

### A4. 뜯었을 때 윗부분 연출

**현재.** 70% 자르면 `Requested` → `PackOpener.TryOpen` → `pack.Consume()`으로 팩이 즉시 사라지고 카드 묶음이 바로 나옵니다.

**설계 (Pocket의 "찢는 맛")** — 개봉 판정은 지금대로 즉시, **연출만 0.6~0.8초 앞에 끼움**:

```text
자르는 중   ─ 그은 만큼 윗부분이 위로 말려 올라감 (진행도 × 최대 각도, 이미 있는 FoldHinge 재사용)
자르기 완료 ─ ① 윗띠가 분리되어 위로 튕김 → 중력으로 떨어지며 0.4초 뒤 사라짐
            ─ ② 팩 틈에서 빛줄기 (등급 색, 노말은 흰색) + "찌익" 소리 + 진동 1회
            ─ ③ 카드 묶음이 팩 안에서 6cm 솟아오르고, 빈 팩은 아래로 빠져 사라짐
            ─ ④ 첫 장 공개 연출 시작 (기존 PackSequence)
```

- 판정은 **개봉 시점 한 번**이므로(설계 4장) 연출 중 그만두거나 페이즈가 바뀌어도 데이터는 같습니다. 연출 중 `Skip`이 가능하게 `Consume`을 연출 끝으로 미루지 않음(팩을 먼저 잠그고 연출만 따로 재생).
- 윗띠는 물리(Rigidbody) 대신 **스크립트 트윈**으로 움직입니다(BUG-003의 Teleport 문제 + Quest 비용).
- 파티클은 쓰지 않고 빛줄기는 쿼드 + 알파로(Quest 성능, 개봉연출 설계 3장).
- 보완: 연출 중 `revealer.IsBusy`와 같은 잠금이 필요 → `PackOpener`의 "여는 중" 판정에 포함.
- 예산: 노말 팩 총합 4초 안(설계 3장)에 포함되도록 0.7초 이내.

### B1 · B2. 결과함 UI와 책상 위 더미, 보관함

피드백이 비슷한 말 두 줄이라 **하나의 흐름으로 합쳐** 해석했습니다. (⚠ 틀리면 알려 주세요)

```text
팩 개봉 → [한 장씩 넘기기] → 넘긴 카드가 책상의 "결과 더미"에 차곡차곡 쌓임
        → 마지막 장을 넘기면 더미 위에 [결과함 UI](이번 팩 5장 요약 + 새 카드 표시)
        → 오른손 트리거 "보관함에 넣기" → 더미가 보관함으로 날아가고 UI가 닫힘
```

| 지금 | 바꿈 |
|---|---|
| 넘긴 카드가 카운터에 가로 5장으로 펼침 (`SlotPosition`) | **한 곳에 쌓임** (카드 두께 3mm씩, 살짝 비뚤게) |
| 5장 모두 펼쳐 보면서 확인 | 결과함 UI에서 요약으로 확인 (다 열었을 때만 표시) |
| 카드는 그냥 카운터에 남아 다음 영업에서 `Clear()` | **트리거로 정리**하는 행동 (뿌듯한 마침표) |

**데이터는 바뀌지 않습니다.** 카드는 개봉 시점에 이미 `Collection`에 들어가 있으므로(설계 5-1) "보관함에 넣기"는 **연출과 정리 행동**일 뿐입니다. 그래서 안전합니다.

**보완할 점**

1. **"보관함" = 바인더인지 확인.** 설계서에는 바인더(표지 소켓 1개, 꽂으면 해당 칸에 자동 배치)가 3일차에 있습니다. 새 저장 시스템을 만들면 중복이므로 **보관함 = 바인더**로 통일하길 권합니다. 바인더가 생기기 전에는 "더미가 위로 사라지는" 임시 연출로 대체.
2. **넣기를 안 하고 다음 팩을 열면?** 막으면 답답하므로 **새 개봉이 시작될 때 이전 더미는 자동으로 보관함에 들어감**. 직접 넣는 것은 "빨리 정리하고 싶을 때"의 선택.
3. **넘기기 트리거와 넣기 트리거가 같은 버튼(오른손 트리거).** 마지막 장을 넘기는 눌림이 곧바로 "넣기"로 이어질 수 있음 → 마지막 장 후 **0.4초 입력 잠금** + 결과함이 완전히 뜬 뒤에만 반응.
4. **더미에 쌓이면 이미 넘긴 카드를 다시 못 봄.** 결과함 UI가 5장을 보여 주므로 대부분 해결. 더미 맨 위 카드만 잡을 수 있게 둘지는 바인더가 생긴 뒤에 결정.
5. 오른손 트리거는 Ray UI 클릭에도 쓰입니다(디버그 패널 등). 레이가 UI를 가리키는 채로 카드를 넘기면 둘 다 반응할 수 있음 → 개봉 연출 중에는 오른손 레이의 UI 상호작용을 끔(`PackSequence` 시작·끝에서 토글) 또는 UI가 가까우면 무시.
6. 지금 `CardRevealer`는 5장을 담는 풀을 쓰므로 더미화 자체는 쉬움(위치만 바꿈).

### B3. 상자 10팩 — 일괄 개봉 연출 + 가벼운 결과판을 합치기 (🔁 보완 중)

사용자 확정: 빠르게 넘기기(트리거 3초 꾹), **유니크·레전더리는 예외로 무조건 보여 줌.**
사용자 질문: 예전 텍스트 방식(가벼움)과 10팩 일괄 연출을 합칠 수 있는가? 스킵하면 한꺼번에 나오는 방식(포켓몬)은?

> ※ 포켓몬 Pocket의 스킵은 "연출을 건너뛰고 결과 화면으로 간다"고 기억하지만 **저는 확인하지 못했습니다.** 실제 영상으로 한 번 확인해 주세요. 아래 설계는 그 확인과 상관없이 성립합니다.

**핵심 아이디어: 연출은 깊이를 고를 수 있는 한 줄 파이프라인으로, 끝은 항상 가벼운 결과판.**

```text
[일괄 개봉 연출] → [공개 대기열] → [결과판]
  10팩 동시 뜯김      ← 깊이가 달라짐 →    기존 텍스트 결과판 + 하이라이트 카드
```

공개 대기열에 **무엇을 넣느냐**만 모드로 바뀝니다. (결과판은 어떤 경로로 와도 같고, 가볍습니다.)

| 모드 | 대기열 | 걸리는 시간 | 언제 |
|---|---|---|---|
| 한 장씩 | 50장 전부 | 약 40초 | 기본값 (처음 요청한 방식) |
| 팩 단위 (선택 후보) | 10팩 × 5장을 한 번에 펼침 | 약 15초 | 한 장씩이 길다고 느낄 때의 중간 |
| **스킵** (3초 꾹) | **유니크·레전더리만** | 약 2~6초 | 그냥 결과가 보고 싶을 때 |

- 스킵을 눌러도 **유니크 이상은 대기열에 남음**: 자동으로 한 장씩 천천히 공개(등급별 멈춤·진동, 설계 3장). 이 구간은 3초 꾹으로 건너뛸 수 없고, 트리거 한 번이 "다음으로"입니다.
- 갓팩(5장이 모두 유니크 이상)은 5번 반복하지 않고 **5장을 한 줄로 동시 공개** 한 번으로 묶음.
- 필요한 시간은 가볍습니다: 유니크·레전더리가 팩당 약 0.10장(슬롯 4: 1.3%, 슬롯 5: 9.0%) → **상자 1개에 평균 약 1장**. 강제 공개 때문에 스킵이 느려지는 일은 거의 없음.
- 수퍼레어는 평균 상자당 약 4.7장. 스킵하면 대기열에는 안 들어가고 **결과판에서 금빛으로 강조**(결과판의 "5점 줄"에서 눈에 띄게).

**가벼운 결과판을 어떻게 개선하나 (텍스트 방식의 장점 유지)**

- 지금: 팩마다 "최고 등급 · 새 카드 수 · 특수 팩" 한 줄 → 어떤 카드가 나왔는지는 모름.
- 개선: 팩마다 **5점 줄** `팩 3  ● ● ● ◆ ★  새 2` — 카드 한 장당 등급 색의 작은 기호 하나. 글자 하나(TMP 1개)로 50장의 등급 분포가 전부 보임. 비용은 지금과 같음.
- 아래에는 지금처럼 **하이라이트 카드 5장**(실제 3D 카드, 새 카드 · 높은 등급 우선)을 펼침. 유니크·레전더리가 이미 강제 공개로 나왔다면 중복되므로 SR 이하 중 새 카드를 우선.
- 카드 오브젝트는 스킵 경로에서 **하이라이트 5장 + 강제 공개용 1~2장**만 필요 → Quest에서 가볍습니다.

**일괄 개봉 연출 (10팩 동시)** — 눈앞 아치에 팩 10장이 펼쳐지고 0.12초 간격으로 윗띠가 뜯김(A4 연출 재사용), 특수 팩은 틈에서 금빛으로 예고. 약 1.5~2초. 팩은 쿼드 몇 장짜리 가벼운 시각용 풀 10개(실제 팩 프리팹 X).

**보완할 점**

1. 판정은 개봉 시점에 끝나 있으므로(설계 4장) **스킵·페이즈 변경·중단은 데이터에 영향이 없음.** 강제 공개 대상은 `PackResult`에서 `rarity ≥ Unique`로 뽑는 순수 함수라 EditMode 테스트로 고정.
2. 3초 꾹은 게이지 + 진동이 조금씩 세짐 (값은 `fastForwardHoldSeconds`, 기본 3초 → 2차 기기 테스트 후 1.5초로 변경).
3. 단일 팩에도 같은 스킵을 적용: 5장 중 유니크 이상만 남기고 결과함으로. 모드 이름·진행기는 하나(`PackSequence(List<PackResult>)`)로 통일.
4. 카드 오브젝트는 맨 앞 3장만 실체화하는 풀 방식(성능). 위 모드들은 모두 이 풀을 공유.
5. B1·B2(더미·결과함·보관함)에 의존: **결과판 = 결과함 UI**. 먼저 B1·B2.

### C1. 헤드셋 재실행 시 일시정지에서 못 벗어남

**원인 (코드 확인).** `GameFlow.OnApplicationPause(true)`가 `IsPaused = true`로 바꿉니다. 그런데 **`IsPaused`를 `false`로 되돌리는 코드가 어디에도 없습니다.** (`GamePhases.cs:75`의 영업 타이머는 `IsPaused`면 계속 return) → 헤드셋을 벗었다 쓰면 영업 시간이 영영 흐르지 않습니다.
같은 이유로 `StartNewSession()`도 `IsPaused`를 초기화하지 않아서 새 게임이 멈춘 채 시작될 수 있습니다.

**설계**

```text
OnApplicationPause(true)  → IsPaused = true (지금과 같음)
OnApplicationPause(false) → 되돌아옴: 일시정지 메뉴를 플레이어 눈앞 1.0m(월드 고정)에 띄움
메뉴                       → [이어서 하기]  [처음부터 다시 시작]
이어서 하기                → 3·2·1 카운트다운 → IsPaused = false (준비할 시간)
처음부터                   → 확인 한 번 더(실수 방지) → StartNewSession + Title로
```

- `PausedChanged` 이벤트를 구독하는 `PauseMenu`(월드 캔버스) 신설. 디버그 패널과 분리(디버그 패널은 개발 전용).
- **영업(`Business`)일 때만 메뉴**를 띄움. 다른 페이즈는 멈출 시간이 없으므로 자동으로 풀어 줌(개봉·퇴근 직전에 메뉴가 뜨면 방해).
- **왼손 메뉴 버튼으로 직접 일시정지**도 같이 추가(VR 표준, 헤드셋 안 벗고도 멈출 수 있음). 1줄.
- Quest 시스템 메뉴(오큘러스 버튼)는 `OnApplicationPause`가 아니라 **포커스 상실**로 오는 경우가 있음 → `OnApplicationFocus(false)`도 같이 처리.
- 보완: 다시 시작할 때 `CardRevealer.Clear()`, 선반 재생성(`DayStarted`), `Sales` 진열 비우기 등이 새 세션에서 다시 연결되는지 확인 필요(`SessionStarted` 구독). 처음부터 다시 시작이 **씬 리로드 없이** 가능한지 테스트로 확인(EditMode 테스트로 "새 세션 뒤 `IsPaused == false`").
- ⚠ **"다시 시작"이 이어하기인지 새 게임인지** 확인 필요. 둘 다 넣는 것으로 설계했음.

### C2. UI 버튼 상하 간격이 너무 좁음

**원인 (`ShopSceneBuilder.CreateDebugPanel`).** 캔버스 500×760 px, `localScale 0.001`이라 **1px = 1mm**. 버튼 높이 0.064 × 760 ≈ 49mm, 간격(0.072 − 0.064) × 760 ≈ **6mm**. 레이 두께 + 손떨림이면 옆 버튼이 눌립니다.

**설계.** VR 버튼 권장은 1m 거리 기준 높이 약 5~6cm, 간격 약 1.5~2cm.

| | 지금 | 제안 |
|---|---|---|
| 버튼 높이 | 49mm | 56mm |
| 간격 | 6mm | 20mm (한 줄 76mm) |
| 캔버스 높이 | 760px | 7개 → 약 1000px (또는 버튼 7개를 2열로) |

- 값을 `ShopSceneBuilder`에 한 번에 정의하는 `VrUiStyle`(높이 · 간격 · 색)로 만들어, 앞으로 만들 타이틀 · 정산 · 최종 UI가 모두 이 규격을 씀. 디버그 패널만 고치면 곧 같은 문제가 반복됩니다.
- 위험한 버튼(재화 +100 같은 치트)과 일반 버튼 사이는 간격을 더 크게.

### C3. 레이가 닿았을 때 반응이 없음

**원인.** `TMP_DefaultControls.CreateButton`의 기본 `ColorTint`는 Highlighted 색이 거의 흰색(0.96)이라 어두운 배경(0.1 0.08 0.14) 위에서 차이가 거의 안 보입니다. 또 레이 선 색은 UI에 닿아도 그대로.

**설계 (싸고 확실한 순서)**

1. **버튼 색 블록 지정**: Normal 어두운 보라 / Highlighted 밝은 노랑 / Pressed 진한 주황 / 글자색도 반전. `VrUiStyle`에서 한 번에.
2. **살짝 커지기**: 올라가면 ×1.05 (`UiHoverFeedback`, `IPointerEnterHandler/ExitHandler`).
3. **햅틱 틱**: 올라가는 순간 그 손에 약한 진동(0.1/0.02초). 이벤트 인자(`TrackedDeviceEventData.interactor`)에서 어느 손인지 알 수 있음.
4. **레이 선 색**: `XRInteractorLineVisual`의 valid / invalid 색을 구분 (UI 위 = 밝은 색, 허공 = 회색). 코드 없이 인스펙터 값으로 가능 (구현 시 XR Origin 레이 설정에서 확인).
5. 소리(호버 '틱', 클릭 '딸깍')는 클립이 생기면 칸만 만들어 둠.

보완: Poke 버튼(`PokeButton`)은 이미 눌림 비주얼이 있으므로 같은 색 규칙만 맞춤.

## 3. 선생님 제안 — 설계만 (구현은 사용자가 결정)

### D1. 팩을 집으면 "지정된 위치"로 이동

**지금.** 왼손 그립으로 잡는 순간 팩이 `머리 위치 + 시선 수평 방향 35cm, 8cm 아래`로 순간이동 (`TearGestureOpen.BeginPresent`). 머리가 어느 쪽인지에 따라 위치가 달라지고, 순간이동이라 어색함.

**설계안: "개봉대(Opening Stage)"**

```text
카운터 앞 고정 위치(예: 플레이어 기준 정면 50cm, 눈높이 -15cm, 약간 기울임)에
 반투명 개봉대 받침이 항상 떠 있음 (평소엔 희미, 팩을 잡으면 밝아짐)
왼손 그립 → 팩이 손에서 개봉대로 0.25초 동안 부드럽게 날아가 안착 (ease-out + 안착 진동)
그립 놓기 → 팩이 개봉대에서 손 쪽으로/선반으로 돌아감
```

| 장점 | 단점 / 위험 |
|---|---|
| 위치가 항상 같아 자르기 판정 · 연출 · 카드 크기(A1)를 한곳에서 조정 | 개봉대가 있는 방향을 안 보고 있으면 찾아야 함 → 팩을 잡은 순간 개봉대 쪽으로 향하는 화살표/빛줄기, 또는 개봉대를 플레이어 시작 위치(`PlayerHeightCalibrator` 기준)에 맞춤 |
| 순간이동 대신 이동 연출 → 멀미 · 어색함 감소 | 앉아서/서서 플레이 시 높이 차이 → 눈높이 보정(1.6m 기준)에 연동 필요 |
| D2(홀로그램 · 입체 UI)의 자리로 연결 | 새 오브젝트 1개 + 이동 코루틴 (BUG-003과 같은 Rigidbody 동시 이동 규칙 적용) |

- `TearGestureOpen`에서 바뀌는 곳은 **`BeginPresent`의 목표 위치 계산 하나**와 이동 애니메이션. 자르기 판정 · 진행도 · 가이드선은 그대로.
- A1(크기 · 거리)과 충돌하지 않음: 개봉대가 정해지면 A1 값은 개봉대 필드로 옮겨 감.

### D2. 홀로그램 셰이더 · 입체적인 UI로 팩 배치

**① 입체적인 팩 배치 (사용자 메모: 평면이 아닌 입체 UI)** — 지금 팩 12개는 평평한 책상(60×50cm) 위 4×3 격자라, 안쪽 줄은 몸을 숙여야 닿습니다.

| 안 | 모양 | 장점 | 단점 |
|---|---|---|---|
| a | **기울어진 진열대** (45°, 3층) | 구현 쉬움(소켓 위치·방향만 변경), 앞줄·윗줄 모두 잘 보임 | 팩 12개가 서 있어 놓친 팩이 미끄러질 수 있음(소켓이 잡아 줌) |
| b | **곡선 호(arc)** 플레이어 둘레 | 팔 닿는 범위 안, 몸을 안 숙임 | 플레이어 위치가 정해져 있어야 함 (눈높이 보정과 연동) |
| c | **회전 캐러셀** (스틱/그립으로 돌림) | 입체감 최고, 공간 절약 | 조작 하나 추가, 칸 12개와 확률 단서(접힘·뒤집힘) 보기 어려움 |

추천은 **a + b 혼합**(기울어진 호 모양 진열대). DEC-001의 단서(접힘 · 뒤집힘 → 앞/뒷면 두 자세)를 유지해야 하므로 소켓은 지금처럼 `AttachFaceUp/Down` 두 자세를 유지.

**② 홀로그램 셰이더**

- 용도 후보: 개봉대 받침(D1), 등급 연출(수퍼레어 이상 홀로그램은 설계서에도 이미 있음 → 3일차 "등급 셰이더"와 통합), 결과함 UI 뒤 배경.
- 구성: **프레넬 테두리 + 가로 스캔라인 + 세로 스크롤 + 알파**. Shader Graph(URP)로 만들면 Quest 단일 패스 스테레오와 호환성 걱정이 없음(직접 HLSL이면 인스턴싱 매크로 필요).
- Quest 위험: 투명 오버드로우. **작은 면적에만** 쓰고, 화면을 크게 덮는 전체 투명 효과는 피함.
- 구현 시기 제안: 등급 셰이더(3일차)와 한 셰이더 그래프를 공유하면 작업량이 늘지 않음.

## 7. 2차 플레이 피드백 — 플레이 흐름 (집·커뮤니티·판매 등록)

> 입력: 시연 후 붙여 준 "플레이 피드백". 접힘은 위 A3에 반영(도그이어). 아래는 **설계 + 보완점 검토**이고 구현은 확정 후입니다.
> 근거 코드: `GamePhases.cs` · `GameFlow.cs` · `SalesRules` · `PopularElementSchedule` · `GameSession`

### 7-1. 현재 루프가 왜 "쉬는 느낌"이 없나

`영업 → 정산 → 퇴근 전(팩 개봉) → 퇴근 → 다음 날 영업`이 전부 **같은 공간 · 같은 조명 · 같은 UI 한 번 클릭**으로 이어집니다. 정산 화면도, 장면 전환도, 하루가 끝났다는 신호도 없습니다. 페이즈 코드(`DayEndPhase`)는 `Enter`에서 바로 다음 날로 넘깁니다.

### 7-2. 집(Home) 페이즈 설계

```text
출근 → 영업 → 정산 → [가게] 팩 개봉(퇴근 전) → 퇴근 버튼
   → 페이드 아웃 → [집] 정리 · 판매 등록 · 커뮤니티 확인 → 침대 → 페이드 아웃 → "N일차" 카드 → 페이드 인 → 영업
```

| 항목 | 설계 |
|---|---|
| 공간 | **같은 `Shop.unity`의 다른 구역**(가게에서 30m쯤 떨어진 위치)에 집 구역을 둠. 씬 2개로 나누지 않음(설계서 "씬은 하나" 결정 유지, 로딩·Quest 메모리 부담 없음) |
| 이동 | `FadeTransition`: 0.6초 검게 → **리그를 집 위치로 이동** → 0.6초 밝게. 이동은 어두울 때만 해서 멀미 없음. 페이드는 화면 전체를 덮는 검은 면(머리 고정이지만 **정지 화면 페이드라 멀미 영향 거의 없음**) |
| 페이즈 | `GamePhaseId.Home = 8`을 추가(enum은 번호가 명시돼 있어 안전). `AfterHours → Home → DayEnd`. 마지막 날(7일)은 집을 건너뛰고 바로 `Final` |
| 집 안 물건 | ① **책상 = 바인더**(3일차) ② **컴퓨터 = 카드 커뮤니티** ③ **침대 Poke 버튼 = 다음 날** |
| 쉬는 느낌 | 가게는 낮 조명 → 퇴근할 때 노을 색으로 전환, 집은 따뜻한 낮은 조명 + 잔잔한 BGM, **타이머 없음**, 잘 때 3초 페이드 + "2일차 아침" 카드 |

**보완할 점 (놓치면 버그가 되는 것)**

1. **들고 있는 물건이 따라옴.** 리그를 옮기면 손에 든 팩 · 카드가 집까지 같이 감. 페이드 전에 모든 잡기를 해제(`CancelInteractableSelection`)하고, 눈앞에 떠 있는 팩(`TearGestureOpen.IsPresented`)도 정리.
2. **퇴근 조건.** 지금 `ClockOut`은 아무 때나 됨 → 카드를 넘기는 중(`revealer.IsBusy`)이면 막고 안내. 더미가 남아 있으면(B2) 자동으로 보관함에 넣고 이동.
3. **안 팔린 진열 카드의 반환 시점.** 지금은 `DayEnd`에서 반환 → 집에서 내일 팔 카드를 등록한 뒤 `DayEnd`가 그걸 지워 버림. **반환을 `Home.Enter`로 옮겨** "안 팔린 카드는 집으로 가져온다"로 만들면 자연스럽고(다시 등록하면 됨), 규칙 변경은 호출 위치 한 곳.
4. **등록 후 가게에 나타나는 방식.** `SalesDisplay`는 이미 **ID 목록 데이터**라, 집에서 등록한 카드를 다음 날 가게 진열대가 **데이터를 읽어 그리기만** 하면 됨(카드 오브젝트를 옮기지 않음).
5. 새 게임 · "처음부터 다시 시작"(C1) 때 리그가 가게로 돌아오는지 확인(`SessionStarted` 시 위치 초기화).
6. 눈높이 보정: 집 구역에서도 같은 바닥 높이면 `PlayerHeightCalibrator` 그대로. 바닥 높이를 다르게 하면 다시 보정 필요 → **바닥 높이는 같게**.

**어디서 팩을 여나?** 두 안:
- **A (추천)** 팩 구매 · 개봉은 지금처럼 가게(퇴근 전), 집은 **정리 공간**. 이미 만든 선반 · 개봉 연출을 그대로 씀.
- B 팩을 사서 **집에서 개봉**: 쉬는 분위기에서 여는 맛은 좋지만 선반 · 카운터를 옮겨야 해서 일정 부담이 큼.

### 7-3. 카드 커뮤니티 — "인기 카드를 확인할 수 있는가?"

**답: 속성 단위는 이미 가능, 카드 단위는 새로 만들어야 함.**
- 이미 있음: `PopularElementSchedule`이 게임 시작 때 **7일 전체 일정**을 뽑아 둠(2일마다 속성 1개, ×1.5). `For(day)`로 오늘 · **내일**을 바로 알 수 있음.
- 없음: "특정 카드가 인기"라는 규칙. 카드 단위를 만들면 가격 규칙(`EconomyRules`)과 테스트를 건드리게 됨.

**설계(추천, 가볍게)**: 집 컴퓨터 화면(월드 UI 1장)에 3칸
1. **오늘의 인기 속성** · **내일의 인기 속성(예보)** — 데이터 그대로 표시
2. **인기 카드 TOP3**: 인기 속성 카드 중 **수퍼레어 이상 중 내 보유 카드**를 가격순으로 → 새 규칙 없이 `Collection`과 `CardDatabase`만 읽음
3. 커뮤니티 분위기 글 2~3줄(고정 문구 + 속성 이름): 예) "불 슬라임 시세 오르는 중!"

효과: 집에서 **내일 인기 속성을 보고 어떤 카드를 내일 진열할지 정하는** 선택이 생겨서, 집 방문이 "쉬는 시간 + 작은 전략"이 됨. (인기 속성은 "일정이 밀리면 가장 먼저 제외"로 적혀 있음 → **이 기능이 들어가면 제외하지 않는 쪽으로 바뀌므로 일정과 함께 결정**.)

### 7-4. 판매 등록 · 즉시 판매

사용자 제안: 수퍼레어 이상만 판매 등록(진열), 등록한 카드는 가게에서 확인, 손님이 살 수도 안 살 수도 있음, 고정 가격 즉시 판매도 가능.

| | **진열 판매** (기존 규칙) | **즉시 판매** (새로 추가) |
|---|---|---|
| 방식 | 카드를 가게 진열대(4칸)에 올림, 손님이 **확률로** 구매 | 집에서 바로 팔고 **그 자리에서 고정 가격** |
| 가격 | 기준가(인기 속성 ×1.5, 수수료 10% 차감) | 고정 = 기준가 × α (α는 아래 보완) |
| 위험 | 안 팔릴 수 있음(확률) | 없음 |
| 대상 | 제안: **수퍼레어 이상** | 제안: 모든 등급(아래) |

**보완할 점 (⚠ 경제 규칙이 바뀜)**

1. **제한을 걸면 노말·레어가 가치를 잃음.** 기준가는 1/5/20/100/500(기획서). 진열이 수퍼레어 이상만이면 노말·레어 중복은 팔 길이 없음. → **즉시 판매는 모든 등급**으로 열어 두면 중복 카드의 쓸모가 남음.
2. **즉시 판매가는 진열 기대값보다 낮아야** "기다릴지 지금 팔지" 선택이 생김. 기대값 = 기준가 × 구매확률(예: 수퍼레어 20 × 확률). 제안 α는 **0.6**(밸런스 시뮬레이터에서 재조정, 5일차). 구매확률 · 가격은 SO 값이라 코드 수정 없이 조정 가능.
3. **구현 위치**: `SalesRules`에 `SellInstantly(session, cardId)`와 `CanDisplay(card)`(등급 제한을 `EconomyConfig.minDisplayRarity`로 데이터화)를 추가. 순수 C#이라 EditMode 테스트로 고정(기존 `SalesAndScoreTests` 확장). 수수료는 즉시 판매에도 같은 10%인지 정해야 함.
4. 즉시 판매가 너무 편하면 진열(손님 · 결제 · 청소) 컨텐츠가 무의미해짐 → α를 낮게 + 하루 판매 횟수 제한 없음으로 시작하고 시뮬레이터로 확인.
5. 이 기능의 UI는 **바인더(3일차)에 의존**: 바인더에서 카드를 골라 "진열 / 즉시 판매" 선택. 바인더 전에는 구현할 자리가 없음.

### 2차 플레이 피드백 반영 — 개봉 규칙 재정리 (2026-11-17, DEC-004 · DEC-005)
- 등급 색 숨김: 카드 묶음은 **뒷면**으로 쌓여 있다가 맨 앞에서 뒤집히며 공개(`CardRevealView.Reveal/Announce`). 팩 뜯을 때 빛줄기도 등급과 무관하게 흰색 · 특수 팩 예고(긴 빛줄기)도 제거.
- 수퍼레어~유니크는 같은 연출(작은 금빛 폭죽 + 같은 진동·멈춤). 레전더리만 큰 폭죽 + **카드 흔들림**(`CardRevealView.Shake`) + 진동. 카메라 셰이크는 VR 멀미 우려로 쓰지 않음.
- 갓팩 전용 5장 동시 공개 삭제 → 일반 팩과 같은 한 장씩. 3초 꾹 건너뛰기는 **전 등급 적용**(남은 카드는 앞면으로 뒤집혀 더미로). `RevealQueue`에서 ForcedOnly · GodRow 삭제, `PickHighlights(skipped)` 인자 삭제.
- 용어: 화면 문구의 "진열"을 "판매 등록"으로 변경(SalesPanel · SalesPanelBuilder). 코드 이름(DisplayResult 등)은 유지.
- 남은 일: ① 카드 뭉치 돌려보기(왼쪽 트리거) ② 벽장 장식 ③ 집 업그레이드 상점(설계서 별도). 원초의 슬라임 규격은 이미지 확인 필요.
- 재빌드: Build Shop Scene (판매 패널 글자 바뀜). 기존 씬의 CardRevealer 직렬화 필드 일부(godRow*, forcedLeadIn)는 삭제돼 경고 없이 무시됨.
- 카드 돌려보기(구현, Unity 확인 전): 결과함이 떠 있는 동안 **왼손 트리거**를 누르면 손 가까이(0.3m, `inspectReach`)의 더미 카드가 손 앞으로 와서 손 회전대로 돌아가고, 놓으면 제자리로 돌아감 (`CardRevealer.InspectPile/HoldCard`). XRI 잡기를 쓰지 않아 기존 입력과 겹치지 않음. 단일 팩 더미만 (상자는 결과판 방식이라 해당 없음). 왼손 레이가 UI를 같이 누르는지는 실기기 확인 필요.
- 3차 수정(Quest 확인 후): 카드 뒤집기 연출 취소(앞면 쌓기로 복귀), 팩 뜯을 때 색 판(빛줄기) 제거(PackTearEffect·BoxOpenEffect), 왼손 돌려보기 제거 → 결과함 단계에서 더미 카드를 일반 잡기로 집어 놓으며 보기, 빈 팩은 작아지지 않고 비틀리며 떨어짐. 팩 프리팹 값이 바뀌었으니 **Build Pack Prefab 재실행** 필요.
- 4차(DEC-007): 개봉한 카드를 **퇴근 전까지 테이블에 쌓아 둠**. 새 팩을 열어도 보관함으로 가지 않고, 결과함의 "트리거: 보관함에 넣기"도 없앰(퇴근 · 상자 개봉 · 60장 초과 때만 보관함으로). 성능: 최근 15장(`pileVisibleCards`)만 실제 카드, 오래된 카드는 옆면 덩어리로 줄임. 팩과 카드 크기는 `packFitRatio`로 맞춤. 퇴근 때 보관함에 보낸 카드 전체를 `PileStashed`로 바인더에 알려 반짝이게 함.
- 5차(DEC-008): ① 상자 10팩 **일렬 배치 + 자르는 선이 한 번 가로지름**(`BoxOpenEffect.rowLayout`, 끄면 기존 아치) ② 갓팩은 건너뛰기 불가: 특수 효과(큰 금빛 폭죽 · 진동, `godIntroSeconds` `godPackSound`) 후 한 장씩, 건너뛰면 갓팩 카드만 마지막에 열림(`RevealQueue.GodOnly`) ③ 더미 카드를 집으면 테이블 더미 전체 요약 판 표시(`CardRevealer.BuildPileInfo`, 오래된 줄인 카드 포함).
