# UI 개편 설계 — MDA로 본 참고 게임과 "장소마다 다른 재질" (11-20, 결정 필요)

> 요청: "지금 UI는 너무 기본 형태라 게임 분위기에 녹아들지 않음. MDA로 다른 게임 UI를 분석해 적용할 점을 찾고, 메인 메뉴 포함 모든 UI를 다시 설계, 샘플 결정 후 구현."
> 샘플(디자인 캔버스 11장): https://claude.ai/artifact/JdreoztaD4HniEkzPQAhgw
> 이전 결정 [DEC-027](../../DevLog/decisions/)(테마 A 카드샵 굿즈 색)은 **색은 그대로 두고 "모양 · 재질"을 바꾸는** 후속안입니다.

## 1. 지금 UI의 문제 (조사 결과)

| 증상 | 원인 (코드) |
|---|---|
| 모든 판이 "공중에 뜬 보라 네모" | `WorldUiKit.AddPanel` = 단색 `Image` + 분홍 띠. 스프라이트 · 9-slice · 그림자 없음 |
| 같은 게임인데 판마다 모양이 다름 | 3D 글자 띠(`<mark>`) · 단색 판 · 종이 메모가 섞임. 하드코딩 색 20곳 이상 (`TutorialCaption`, `ShopTimerBoard`, `PosTerminal`, `MarketScreen`, `SpeechBubble` …) |
| 가게 물건과 UI가 따로 놂 | 메모 · 수칙 종이만 "가게 물건"이고, 정산 · 일시정지 · 판매 · 타이틀은 화면용 패널 |
| 글자 인상이 밋밋함 | 글꼴 1종(NotoSansKR Regular). 제목 · 본문 · 숫자 구분 없음 |
| 보상 순간이 덜 특별함 | 팩 결과도 정산과 같은 검은 띠 → 일과 보상의 화면 차이가 없음 |
| 알림이 안 보임 | `RaiseNotice`(도둑 · 바코드 · 청소 경고) 구독자가 디버그 판뿐 (기기 확인 필요) |

## 2. MDA로 본 참고 게임

MDA: **M**echanics(규칙 · UI 장치) → **D**ynamics(플레이 중 생기는 행동) → **A**esthetics(느끼는 재미). 참고 게임의 UI가 어떤 장치로 어떤 행동 · 느낌을 만드는지 보고, 우리 게임에 가져올 장치만 골랐습니다.

| 게임 | M (UI 장치) | D (생기는 행동) | A (느낌) | 우리에게 가져올 것 |
|---|---|---|---|---|
| **Job Simulator / Vacation Simulator** (VR) | 메뉴 · 설정이 모두 잡고 누르는 물건 (카트리지 넣으면 시작, 손잡이 돌리면 볼륨) | 손으로 만져 보며 메뉴를 "놀이"처럼 탐색 | 몰입, 장난스러움 | 메인 메뉴 = 가게 앞 **입간판**, 일시정지 = 손에 드는 **클립보드**, 버튼은 두께 있는 "누르는 물건" |
| **TCG Card Shop Simulator** | 가게 PC의 OS 창으로 주문 · 가격 확인, 진열대 가격표 | 하루 끝에 PC 앞에서 다음 날 계획 | 가게 주인 판타지, 관리 | 집 컴퓨터 = 레트로 OS 창(**SlimeOS**), 판매가는 진열대와 같은 **가격표 꼬리표** |
| **Pokémon TCG Pocket** | 등급별 연출 크기 차이, 도감 빈칸, 등급 기호(◆ · ★) | 빈칸을 채우려 한 팩 더 | 기대감, 수집욕 | 보상 화면만 **카드(톱로더 · 금박)** 재질, 바인더 빈칸 "?", 등급 = 색 + 기호 |
| **Papers, Please** | 하루 끝 항목별 정산서 (수입 − 지출) | 한 줄씩 읽으며 오늘을 돌아봄 | 노동의 무게, 결과 확인 | 정산 = POS가 **한 줄씩 인쇄하는 영수증** |
| **Balatro** | 점수가 굴러 올라가고 흔들림, 마지막에 "쾅" | 숫자 오르는 걸 지켜봄 | 짜릿함(juice) | 돈 숫자 **굴러 올라가기**, 정산 도장 "쾅", 지갑 +$ 튀어 오름 |
| **Animal Crossing: New Horizons** | 이름표 붙은 말풍선, 한 글자씩 나오는 대사, 둥근 UI | 대사를 끝까지 읽게 됨 | 귀여움, 편안함 | 말풍선에 **이름표**(손님 · 사장님 · 혼잣말 색 구분), 타자 효과 |
| **Half-Life: Alyx** (VR) | 체력 · 탄약이 손등 · 총에 붙은 정보 | 고개를 돌려 손을 봄 | 화면 밖 HUD 없는 몰입 | 손목 재화 = 손목의 **SLIME PAY 카드** (검은 띠 대신 물건) |
| **Overcooked / Cook-Out** | 주문서 티켓 + 기다림 게이지 | 급한 주문부터 처리 | 바쁨, 긴장 | (새 제안) 계산대 **주문 쪽지** + 기다림 게이지 |

**정리 — 세 가지 원칙**
1. **UI는 가게 물건이다 (Diegetic)**: 떠 있는 판 대신 입간판 · 영수증 · 클립보드 · 가격표 · 모니터. VR에서 몰입을 깨지 않는 가장 큰 차이.
2. **일과 보상은 재질이 다르다 (대비)**: 알바 일 = 종이(수수함), 팩 보상 = 카드 · 금박(반짝임). 평소가 수수해야 보상이 커 보임.
3. **바뀌는 숫자는 움직인다 (Juice)**: 돈 · 개수 · 도장은 굴러 오르고, 튀고, 소리가 남.

## 5. 공통 규칙 (스타일 가이드, 샘플 1번 판)

- **색**: DEC-027 색 유지 + `Paper`(#FBF5E6) · `Receipt`(#FFFEF8) · `Ink`(#2B2140) · `Kraft`(#C79A62) · `Sticky`(#FFE98A) · `MoneyPlus`(#2FA37C) · `MoneyMinus`(#D9434F) 추가. 하드코딩 색을 모두 `UiTheme`로.
- **글꼴 하나 (11-20 사용자 결정, 처음 안 "글꼴 4종"을 바꿈)**: 모든 글자 **Noto Sans KR Bold**, 색 강조는 그대로.
  - 굵기가 같으니 **크기 3단계**로 나눔: 제목 44 · 본문 28 · 보조 20 (`UiFonts.TitleSize/BodySize/SmallSize`).
  - 진짜 Bold 에셋(`Resources/Fonts/NotoSansKR-Bold SDF`, 메뉴 `CardShop/UI/Bold 글꼴 에셋 만들기`)을 씀. 없으면 Regular + 굵게 표시(작은 글자가 조금 뭉개질 수 있음).
  - 다른 글꼴이 맡던 역할은 다른 방법으로: 손글씨 느낌 = 메모지 색 · 기울임 · 줄 긋기, 영수증 숫자 정렬 = TMP `<pos>`.
  - 종이 위에서는 밝은 강조색을 같은 계열의 진한 색으로 (밝은 초록 → #2FA37C, 분홍 → #ED5C99). `UiSkin.PaperColorFor` 한 곳.
- **버튼**: 둥근 모서리 + 아래 두께(그림자). 가리킴 = 분홍 + 1.06배, 누름 = 두께만큼 내려감 + 진동.
- **등급 표시**: 색 + 기호(◆ 노말 · ◆◆ 레어 · ◆◆◆ 수퍼레어 · ★ 유니크 · ★★ 레전더리)를 모든 화면에서 같게. 색은 `CardRarityStyles` 테두리 색 그대로.
- **VR 글자 크기**: 1m 거리 기준 글자 높이 16mm 이상.

| 단계 | 할 일 | 새 클래스 / 고치는 곳 |
|---|---|---|

- 기존 클래스에 넣지 않고 새 클래스로 나누는 이유: 재질 · 글꼴 · 움직임은 여러 화면이 같이 쓰는 기능이라 화면 클래스 안에 두면 같은 코드가 반복됨 (AI-005).
- 퀘스트 성능: 스프라이트는 아틀라스 하나로 묶고, 빛 효과는 셰이더 대신 스프라이트 알파로 (블룸 없음).

## 구현 방식 (11-20 1차)
- 11-20부터 `Shop.unity`가 원본이라 **씬을 다시 만들지 않고**, 각 화면 스크립트가 Awake에서 `UiSkin.ApplyPanel`로 재질을 입힘 (씬의 배치 · 크기는 그대로).
- 재질 그림은 파일 없이 코드로 만듦 (`UiSprites`: 둥근 판 9-slice · 테두리 · 원 · 영수증 톱니). 실행할 때만 입힘(코드 스프라이트는 씬에 저장되지 않음).
- 1차 적용: 정산 영수증(`ReceiptPrinter` 한 줄씩 인쇄 + `SettlementStamp` 도장) · 타이틀 칠판 입간판(+ [출근하기]) · 일시정지 클립보드 · 최종 상장 종이 · 팩 결과 카드판(`TextPlate`) · 알림 쪽지(`TextPlate`) · 모든 버튼 둥근 모서리 + 두께.
- 2차 (11-20): 말풍선. 사장님 · 혼잣말(`BossBubble`)과 튜토리얼 자막(`TutorialCaption`)을 종이 말풍선(`PaperBubble`)으로. 사장님 = 노랑 실선, 혼잣말 = 하늘색 점선(`UiSprites.DashedFrame`), 왼쪽 위 이름표(`NameTag`). 자막의 할 일 = 진한 분홍, 완료 = 진한 초록. 손님 구름 말풍선은 모양 그대로 두고 분홍 "손님" 이름표 + 한 글자씩(`TypewriterText`). 톡톡 소리는 클립이 없어 아직 없음.
- 보이는 방식 (11-20 "자막 · 사장님 말풍선이 가끔 안 보임"): 퇴근 · 아침 혼잣말(`DayTransition` → `WorldToast`: 말할 때 정면에 한 번 놓고 월드 고정)을 따름.
  - 사장님 말풍선: 정면 높이 15cm → 5cm 아래(혼잣말과 같게) + 맨 위에 그리기(눈앞에 든 팩 · 진열대에 가려졌음).
  - 자막(`CaptionPlacement`): 새 안내 때 정면에 고정(예전: 지평선 기준 32° 아래 + 35° 넘으면 따라옴 → 위를 보면 시야 아래로 빠짐). 수평 · 아래를 볼 땐 수평 10° 아래(손을 가리지 않게), 위를 볼 땐 시선 10° 아래로 따라 올라감(최대 40°). 시야(50°) 밖이 1초 이어지거나 1.5m 넘게 걸어가면, 또는 가만히 있어 다시 알릴 때 정면에 다시 놓음.
- 3차 (11-20, 나머지 전부 — Play 확인 전):
  - **집 PC = SlimeOS** (`HomeComputer`, 새 `SlimeOsWindow` · `ComputerTaskbar` · `CommunityWindow`): 청록 바탕화면 + 쪽마다 창(진보라 몸통 · 연보라 테 · 제목 줄 · 창 단추 셋) + 아래 작업 표시줄(쪽 탭 · "N일차 · 밤"). 커뮤니티는 3D 글자 대신 창 안 캔버스 글자(`CommunityScreen.Rehost`). 판매 · 진열(DEC-042)도 창 두 장 + 위 알림 띠(내일 인기 · 고른 카드).
