## 1. 버그

### B1 대걸레 쥐면 화면이 오른쪽으로 계속 돔 (멀미)
**증상**: 대걸레를 쥔 채 방향을 바꾸려고 움직이자 화면(카메라)이 오른쪽으로 계속 돔. 청소를 마치고 대걸레를 놓으니 멈춤.

**확인한 것 (원인 아님)**
- 대걸레 ↔ 플레이어 몸(CharacterController) 충돌은 `Broom.Start`에서 이미 끔.
- 잡고 스틱 돌리기(조작 입력)는 양손 모두 꺼져 있음(`m_UseManipulationInput: 0`, DEC-017). 잡아 끌어 이동(Grab Move)도 꺼져 있음.
- 왼손 스틱은 이동, 오른손 스틱은 부드러운 회전(90도/초). 왼손에도 "부드러운 회전 켬"이 들어가 있지만 이동이 켜져 있으면 XRI가 회전을 끄므로 영향 없음.

**남은 후보**
1. **멀리서(레이로) 쥔 상태 + 오른손 스틱**: 쥔 채 오른 스틱을 살짝 밀면 회전 — 손을 떼도 계속 돈다면 입력이 "눌린 채"로 남는 경우.
2. **대걸레 막대가 손 · 머리 쪽 다른 충돌체를 밀어** 리그가 돔 (몸 말고 다른 충돌체는 무시 목록에 없음).
3. **오른손으로 쥐고 오른 스틱에 엄지가 얹힘** (기기 스틱 쏠림). 놓는 순간 손 자세가 바뀌어 멈춘 것처럼 보임.

**제안**
- 먼저 질문 Q1(어느 손 · 가까이/레이 · 어느 스틱)으로 후보를 줄입니다.
- 개발 빌드 전용 **회전 기록기**(`RigTurnProbe`, 새 클래스): 리그가 1초에 30도 넘게 도는데 회전 입력이 0이면 "무엇을 쥐었는지 · 양 스틱 값 · 쥔 영역(가까이/레이)"을 로그와 F9 기록에 남김. 다음 빌드 테스트 때 한 번 재현하면 원인이 확정됨.
- 원인 확정 전 안전장치(선택): 대걸레를 쥐고 있는 동안 **회전 입력이 없으면 리그 회전을 막음**은 부작용(정상 회전도 막을 수 있음)이 있어 추천하지 않음.

### B2 쓰레기통에 여전히 올라탐
**확인한 것**: 통 자리(`TrashBinZone`)에 보이지 않는 막는 상자(0.5 × **1.1** × 0.5m)가 생기고, 통 모델(0.31 × 0.40m)을 다 덮음. 플레이어 몸이 넘을 수 있는 턱은 0.5m라 상자만으로는 못 올라가야 정상.

**추정 원인**: **손에 든 쓰레기를 몸이 밟고 올라감.** 쓰레기(청소 물건)는 잡혀도 충돌체가 살아 있고, 몸 충돌을 끈 것은 대걸레뿐입니다. 통 위에서 쓰레기를 내리려고 허리 아래로 들면 쓰레기가 발 앞 0.5m 안에 들어와 "턱"이 되고, 그 위로 올라선 뒤 통 위에 서게 됩니다 (VR에서 흔한 "들고 있는 상자 밟고 뜨기").

**곁에서 찾은 것**: 씬의 통 입구 반지름이 **0.32**로 저장돼 있어 11-20에 코드에서 바꾼 0.4가 적용되지 않았음 (씬 값이 우선).

**제안**
- `HeldBodyGuard`(새 클래스, 리그에 스스로 붙음): **무엇이든 손에 쥔 동안** 그 물건 충돌체 ↔ 플레이어 몸 충돌을 끄고, 놓으면 다시 켬. 쓰레기 · 흐트러진 팩 · 카드 · 상자 · 스캐너 모두 해당. `Broom.Start`의 같은 처리는 이쪽으로 합침.
- 막는 상자 높이 1.1 → 1.6m (머리 위까지는 안 가게) — 보험.
- 씬 `TrashBin.radius` 0.32 → 0.4.

### B3 판매 등록이 매일 풀림
**원인**: `HomePhase.Enter`가 `ReturnUnsold`로 안 팔린 판매 등록 카드를 **매일** 보유 목록으로 돌려놓음. 시연 피드백 때 "집에서 다시 고를 수 있게" 넣은 동작이 지금은 불편함이 됨.

**제안 (추천 A)**
- A. **판매 등록은 내가 내릴 때까지 유지.** 매일 반환을 없애고 마지막 날(최종 점수 직전)에만 돌려놓음(이미 있는 `ReturnUnsoldOnFinalDay`). 판매 패널에 [모두 내리기]가 없으면 추가.
- B. 반환은 하되 "어제 목록 다시 등록" 버튼 하나 — 버튼이 늘고 결국 같은 일을 매일 누름.
- 바뀌는 테스트: 집 도착 반환을 기대하는 EditMode 테스트가 있으면 함께 고침.

### B4 진열장에 놓아도 안 보임 · 매일 풀림
**원인 추정**: 지금 흐름은 ① 진열 패널 [진열장에 세우기] → ② 카드가 **바인더 위 0.3m에 떠오름** → ③ 손으로 집어 모니터 위 보관함 칸에 꽂아야 저장. ③을 안 하면 보관함은 비어 있고, 집을 나가면 떠 있던 카드가 사라짐 → "놓아도 안 보이고, 다음 날 또 풀림"과 증상이 맞음. 보관함이 모니터 위(틀 위 끝 약 2.2m)라 눈에 잘 안 띄는 것도 겹침.

**제안 (추천)**
- 버튼을 누르면 **바로 첫 빈 칸에 꽂힘** — 카드가 바인더에서 보관함 칸으로 날아가는 0.5초 연출 + 소리 + 진동 (데이터는 누르는 순간 확정).
- 손으로 하는 일은 **옮기기 · 바인더 위로 내리기만** 남김 (지금 코드 그대로).
- 처음 진열하면 한 번만 "모니터 위 보관함에 세웠어요" 안내.
- DEC-034의 "꺼내기를 손으로"를 고치는 것이라 **결정 기록 갱신**(DEC-034에 "11-20 플레이 뒤 바뀜" 추가 또는 DEC-036).
- `CardCase` 295줄 → 꺼내기(Loose) 부분이 빠져 약 260줄 예상, 맡은 일 안.

### B5 지난 판 업그레이드가 남음
**확인한 것**: [출근하기]와 일시정지 [처음부터]는 모두 새 세션을 만들고, 방 가구 · 택배 상자 · 상점 화면 · 보관함 칸 수는 새 세션을 따라 처음으로 돌아갑니다. 저장 기능이 없어 앱을 완전히 끄면 남을 것이 없습니다.

**가능성**: Quest에서 앱을 **완전히 종료하지 않고**(헤드셋을 벗었다 쓰거나 홈 메뉴로 나갔다 들어옴) 이어서 한 경우 → 이전 판이 그대로 이어짐. 질문 Q3로 확인한 뒤, 코드 문제가 맞으면 재현 순서를 받아 고칩니다.

## 2. 새 기능

### F1 레어도 정렬 버튼 (바인더)
- 바인더 속성 탭 줄 오른쪽 끝에 버튼 하나: **[도감순] ⇄ [레어도순]** (누를 때마다 바뀜, 글자 = 지금 정렬).
- 레어도순 = 레전더리 → 유니크 → 수퍼레어 → 레어 → 노말, 같은 등급 안에서는 도감 순서.
- 속성 탭과 함께 씀 (예: 불 탭 + 레어도순). 탭 · 정렬을 바꾸면 1페이지로.
- 구조: 순수 C# `BinderSort`(새 클래스, 정렬 규칙 + 테스트) → 거른 ID 목록을 정렬해 `BinderLayout`에 넘김. `BinderView`(295줄)에는 정렬 상태 한 줄 · 버튼 연결만.
- `[결정 필요 Q4]` 보유한 카드를 앞으로 모으는 "보유순"도 넣을지.

### F2 슬라임 얼굴 도장
- 그림 3장(등급별)을 받아 분홍 고리 + 글자 대신 그림을 찍고, 문구는 그림 아래 작게. 그림이 없으면 지금 도장 그대로 (그림 없이도 빌드가 깨지지 않게).
- 규격은 5-1.

### F3 레어 등장 소리 · F4 카드 집기 소리
- F3은 사용자가 클립을 고름 (넣는 자리는 5-2). 이번 빌드는 PR #2 전이라 **임시 음높이 클립**을 들으신 것 — 다음 빌드의 Pixabay 클립을 먼저 들어 보고 고르셔도 됩니다.
- F4: `SoundId.CardPick`(빈 번호 6) 새 칸, 카드를 손에 쥐는 순간(공개 카드 · 보관함 카드 · 바인더에서 꺼낸 카드) 재생. 칸이 비면 소리 없음. 연달아 쥘 때 겹치지 않게 0.1초 간격.

### F5 가구 업그레이드가 눈에 보이게
| 분야 | 지금 | 제안 |
|---|---|---|
| 침대 | 처음 `Bed2_01` → `Bed2_02` → `Bed2_03` (같은 2인용 모양을 바꿔 끼움, 자리 · 크기 그대로) | **0단계 1인용 `Bed1_01`** → 1단계 2인용 `Bed2_02` → 2단계 `Bed2_03`을 **1.25배** (킹). 벽 쪽 모서리를 맞춰 커지게(지금 `Replace`는 원래 크기를 복사하므로 `scale` · 모서리 맞춤 칸 추가) |

| 바인더 | 2단계에 `NoteBook_02`를 책상에 둠 | `NoteBook`이 노트북(컴퓨터) 모델이면 컴퓨터와 헷갈리므로 → 책 더미(`Book_0x`)로 바꿈 |

- 침대 모델 크기(1인용 · 2인용 실제 폭)는 에디터에서 눈으로 확인 필요 → 업그레이드 단계 미리보기 메뉴(`Tools > CardShop > Home > Preview Upgrade Level`)를 함께 만들면 Play 없이 확인 가능.
- `[결정 필요 Q5]` 침대 0단계를 1인용으로 바꿀지 (처음 방이 조금 비어 보임).

### F6 에어컨
- 새 분야 `UpgradeKind.AirCon = 8`, 꾸미기 1단계, **$35**(포스터 15 · 러그 20 · 조명 25 · 피규어 30 다음).
- 모델 `LowPoly:Room/AirCondition`, 침대 쪽 벽 위 (높이 약 2.1m). 산 뒤 아침 택배 → 열면 달림 (다른 가구와 같음).
- 덤(선택): 켜져 있으면 집에서 낮은 "윙" 소리 — 칸만 만들고 비워 둠.
- 상점 화면 격자 4열: 8개(2줄) → 9개(3줄). 2.6m에서 3줄이 읽히는지 Play 확인.
- `[결정 필요 Q6]` 효과 없는 꾸미기로 둘지, 작은 효과(예: "다음 날 아침 기분 좋음 → 손님 인내심 +5%")를 줄지.

### F7 맵 수정 도구: 집 업그레이드 가구 자리
- 지금 가구 자리는 `UpgradeCatalog`의 좌표(집 실내 기준)뿐이라 씬에서 못 옮김.
- 제안: 바꿔 끼우지 않고 **새로 놓는 가구**(노트북 · 조명 · 포스터 · 피규어 · 에어컨 등)마다 자리표 `Home/Upgrade/<분야>_<단계>_<번호>`를 목록에 자동으로 추가. 미리보기 상자 = 그 모델 크기.
  - 자리표가 있으면 그 자리, 없으면 지금 좌표 (사장님 메모 · 보관함과 같은 방식).
  - 바꿔 끼우는 가구(침대 · 러그)는 원래 가구를 옮기면 따라가므로 목록에 안 넣음.
- 구조: `MapAnchorCatalog`에 고정 목록 + **카탈로그에서 만든 목록**을 합침 (`UpgradeAnchorEntries`, 새 클래스). `RoomUpgradeView.ApplyFurniture`(214줄)에서 자리표 확인 한 줄.

## 5. 사용자에게 받을 것

### 5-1. 슬라임 얼굴 도장 그림 규격
정산 영수증 오른쪽 아래에 찍히는 도장(지금 130 × 130 크기의 분홍 고리 + 글자)을 그림으로 바꿉니다.

| 항목 | 규격 |
|---|---|
| 장수 | **3장** — 놓친 일 0개 `Great`(활짝 웃음) · 1~2개 `Good`(보통 미소) · 3개 이상 `Weak`(울상 · 땀) |
| 크기 | **512 × 512 px**, 정사각형 |
| 배경 | **투명 PNG** (32bit, 알파 있음) |
| 모양 | 원형 도장 안에 슬라임 얼굴. 가장자리 **24px 여백** (도장 기울임 · 크기 연출 때 잘리지 않게) |
| 색 | **흰색(또는 검정) 한 색**으로 그리면 코드에서 분홍 · 주황 · 회색으로 물들임(도장 잉크 느낌, 추천). 여러 색으로 그리면 색 그대로 씀 — `[Q8]` |
| 선 굵기 | **최소 20px** (영수증 위에서 실제로 약 6~7cm로 보여 가는 선은 뭉개짐) |
| 글자 | 그림에 글자는 넣지 않기를 추천 ("참 잘했어요" 같은 문구는 코드가 그림 아래에 작게 씀 — 문구를 바꾸기 쉬움) |
| 파일 이름 · 자리 | `Assets/04. Art/UI/Stamps/Stamp_Great.png` · `Stamp_Good.png` · `Stamp_Weak.png` |
| 가져오기 설정 | Texture Type **Sprite (2D and UI)**, Alpha Is Transparency 켬, Max Size 512, Generate Mip Maps **켬**(VR에서 멀리 볼 때 반짝임 방지) — 넣어 주시면 제가 설정합니다 |

덤: 무한 모드 사직서 봉투의 "제출" 도장(빨강)도 같은 그림(`Great`)으로 바꿀 수 있습니다 — 원하시면.
