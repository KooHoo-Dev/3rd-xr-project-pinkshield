## 1. 증상 (문제)
- **기대**: 선반의 카드팩을 집은 채 트리거를 당기면 팩이 개봉되고 카드 5장이 카운터에 나온다.
- **실제**: 팩은 잡히지만 트리거를 당겨도 아무 반응이 없다. 에러 메시지도 보이지 않는다.

> 📷 before 없음 — 수정 전에 촬영하지 못했습니다. 화면상 "반응 없음"이라 사진보다 프리팹 YAML(`m_Script: {fileID: 0}`)이 증거입니다.
> (선택) 커밋 `2beb829` 시점의 Pack.prefab을 열면 Inspector에 "Missing Script"가 보여서 before로 찍을 수 있습니다.

## 2. 재현 단계
1. Shop 씬 빌드를 Quest에서 실행
2. 선반의 팩을 그립으로 집음
3. 트리거를 당김 → 반응 없음

재현율: 항상

## 3. 콘솔 로그
```text
(실기기라 로그 없음. 프리팹 파일에서 확인한 내용)
Assets/03. Prefabs/Packs/Pack.prefab
  m_Script: {fileID: 0}
  m_EditorClassIdentifier: CardShop.Runtime::CardShop.Interaction.ActivatePackOpen
```

## 4. 원인
트리거 개봉을 담당하는 `ActivatePackOpen` 클래스가 `PackView.cs` 파일 안에 함께 들어 있었습니다.
Unity는 **MonoBehaviour 클래스 이름과 파일 이름이 같아야** 그 스크립트를 에셋(프리팹)에 저장할 수 있습니다. 그래서 `PackPrefabBuilder`가 `AddComponent<ActivatePackOpen>()`으로 붙인 컴포넌트가 프리팹에 저장될 때 스크립트 참조가 비었습니다(`m_Script: {fileID: 0}` = Missing Script).

- 팩을 집는 기능은 `XRGrabInteractable`이라 정상 → "잡히는데 안 열림"으로 보임
- `PackView.Awake`가 `GetComponents<IPackOpenMethod>()`로 개봉 방식을 찾는데, 스크립트가 없으니 아무것도 연결되지 않음 → 에러 없이 조용히 실패
- 같은 파일 구조였던 `CardRevealView`(CardRevealer.cs 안)는 실행 중에 `AddComponent`로만 붙여서 문제가 드러나지 않았음

## 5. 해결
- `ActivatePackOpen`을 `Interaction/ActivatePackOpen.cs`로 분리하고, `Pack.prefab`의 비어 있던 `m_Script`를 새 스크립트 GUID로 다시 연결
- 같은 함정을 막기 위해 `CardRevealView`도 `Presentation/CardRevealView.cs`로 분리
- 회귀 테스트 `SceneSetupTests.PackPrefab_HasNoMissingScriptsAndOpenMethod` 추가: 팩 프리팹 전체에 Missing Script가 0개인지, `IPackOpenMethod`가 붙어 있는지 검사

고려한 다른 방법: `Tools > CardShop > Build Pack Prefab`을 다시 실행해 프리팹을 새로 만드는 방법. 파일 분리 후라면 이것도 되지만, 프리팹 한 줄만 고치면 되므로 직접 재연결했습니다.

## 6. 결과
- Unity 배치 모드 EditMode 테스트 33/33 통과 (새 테스트 포함)
- **Quest 실기기 재확인은 아직** → 다음 빌드에서 확인 후 이 칸에 결과·after 스크린샷 추가

참고: 개봉은 `AfterHours`(영업 종료 후) 페이즈에서만 됩니다. 영업 중에는 디버그 패널에 안내 글자만 나오므로, 실기기 확인은 퇴근 후 페이즈에서 해야 합니다.

> 📷 after 없음 — 이후 개봉 방식이 "든 손 트리거(ActivatePackOpen)"에서 "자르기(TearGestureOpen)"로 바뀌어, 이 버그의 수정 결과를 같은 방식으로는 더 찍을 수 없습니다.
> 수정이 유효하다는 근거는 회귀 테스트 `PackPrefab_HasNoMissingScriptsAndOpenMethod` 통과와, 같은 프리팹의 새 컴포넌트(TearGestureOpen)로 개봉된 BUG-002/003 after 캡처입니다.

## 8. 배운 점
- MonoBehaviour는 한 파일에 하나, 파일 이름 = 클래스 이름. 어기면 컴파일 에러 없이 프리팹에서만 조용히 빠진다.
- "에러 없이 반응 없음"은 Missing Script를 먼저 의심. 프리팹 YAML의 `m_Script: {fileID: 0}`로 바로 확인할 수 있다.
