## 내 요청
- 씬을 꾸밀 때 **게임을 실행해야만 보이는 물건**(안내 판 · 포스터 · 시계 · 일시정지 메뉴 · 집 소품 등)은 편집 화면에서 보이지 않아 자리를 잡기 어려웠다. 이 도구를 만들기 직전에도 Shop 씬 장식함 · 메모함 자리를 손으로 임시 수정했다(`8bca743`).
- 요청: "도구를 켜면 게임 시작 뒤에 나오는 오브젝트가 모두 나타나고, Transform을 직접 조정해 저장한다." (설계 문서 0장)

## AI 제안
요청을 그대로 만들면 생기는 문제를 먼저 짚고, 7가지를 보완해 설계 · 구현했다(`796e5f6`, 28파일 · 테스트 `PlacementAnchorTests`).

| 요청 그대로 만들면 생기는 문제 | AI 보완 |
|---|---|
| 물건마다 **저장할 곳이 다르다**: 씬에 꺼져 있는 것 / 실행 중 씬 Transform을 따라가는 것 / 실행 중 코드 숫자로 자리가 정해지는 것 | 세 종류로 나누고, 세 번째(안내 판 · 수칙 포스터 · 시계 · 사직서 · 택배 상자 줄 5곳)는 새 자리표 `PlacementAnchor`를 읽게 바꿈. 자리표가 없으면 예전 기본 자리 → 기존 게임은 그대로 |
| Play 중에 옮긴 값은 Play를 끄면 사라짐 | Play가 아니라 **편집 모드**에서 꺼진 것을 켜고, 실행 중에 생길 물건은 실제 크기의 반투명 모형으로 보여 줌(씬에 저장 안 됨) |
| 켠 채로 저장하면 **게임 첫 상태가 망가짐**(일시정지 메뉴가 처음부터 뜸 등) | 끝내기 · Play 시작 · 저장 직전 · 씬 닫기 · 스크립트 재로드 때 도구가 켠 것만 다시 끔. 프리팹의 "켜짐" 오버라이드도 되돌림 |
| `Build Shop Scene`이 씬을 새로 만들면 손 작업이 사라짐 | 이름표(`PlacementKey`) · 자리표는 빌드 전에 기억했다가 되살림(`HierarchyPath`, `AnchorMemory`) |
| 가구를 옮겨도 손님 지점은 안 따라와 겹칠 수 있음 | 손님 동선 지점 · 길을 씬 뷰에 그림(`RouteGizmoDrawer`) |

## 내 판단
- **도구를 써서 디테일 작업**: 거리 소품 약 22개 삭제 · 일부 위치 조정, 건물 모서리 2개 추가, 자리표 5개 배치 → 씬 확정(`2271d59`).
- **씬 관리 방식을 바꿈**: 디테일만 남은 단계라 `Build Shop Scene`을 더 안 쓰겠다고 판단했다.
  - AI는 그 판단에 동의하면서 **지우지 말고 잠그기**를 제안했다. 이유: 씬이 망가졌을 때 처음 상태로 돌아갈 수단이고, 코드로 씬을 만들던 구조 자체가 설명할 거리임.
  - 사용자가 받아들여 메뉴를 `초기화/Rebuild Shop Scene`으로 옮기고, "다시 실행" 안내 문구를 "씬에서 직접 연결"로 바꿈(`047b109`).
- **AI 설계의 빈틈**: AI가 넣은 "빌드 뒤에도 유지" 장치는 **위치만** 지킨다. 오늘 한 거리 소품 삭제 · 추가는 프리팹 위에 씬에서 덧씌운 수정(오버라이드)이라 지켜지지 않는다. 사용자가 빌더를 그만 쓰자고 했을 때 AI가 확인하다 이 빈틈을 찾았다. 사용자의 판단 덕분에 빌더를 한 번 더 돌려 작업을 잃는 일을 피했다.
- 도구를 써 보며 "끝내기를 누르면 수정 전으로 돌아가나?"를 확인함. 답: 보기 상태만 되돌리고, 옮기기 · 추가 · 삭제는 남음. 저장은 Ctrl+S로 따로 해야 함.
- **처음 의도**: 코드로 배치할 때도 결국 Transform 수치를 쓰므로, 손으로 조정한 위치 값을 `Build Shop Scene`에 반영하려고 했다(빌더를 계속 쓰는 전제). 그래서 요청이 "꺼내서 Transform 조정 → 저장"이라는 단순한 형태였다.
- **판단이 바뀐 근거**: 게임 루프는 완성됐고, 이후 작업은 디테일을 위한 기능 추가뿐 큰 기능 추가는 없다 → 씬을 코드로 다시 만들 일이 없으니 빌더에 값을 되돌려 넣을 필요도 없다.

## 결과
- 실행해야만 보이는 물건도 편집 화면에서 보고 옮길 수 있게 됨. 저장해도 게임 첫 상태는 그대로.
- 코드 숫자로 박혀 있던 자리 5곳이 씬에서 옮길 수 있는 자리표가 됨. 앞으로 새 물건은 `PlacementAnchor.Find` + `MapAnchorCatalog` 한 줄로 추가.
- 씬 관리: 코드가 씬을 만드는 단계 → **저장된 `Shop.unity`를 원본으로 직접 다듬는 단계**로 전환(11-20).
- 체감: 예전 방식(코드 숫자 고치기 → Build Shop Scene → Play로 확인)보다 **원하는 위치에 바로 놓고 작업할 수 있어 아주 만족**.

## 참고: 지금까지의 씬 빌딩 구조 (11-16 ~ 11-20)
- `Tools > CardShop > Build Shop Scene` 한 번으로 빈 씬에서 `Shop.unity` 전체를 코드로 만들었다(`ShopSceneBuilder.Build`, 11-16 첫 커밋 이후 24번 수정).
- 순서: 설정 에셋 · 카드/팩 프리팹 → **손으로 옮긴 자리 기억**(`PlacementMemory` · `AnchorMemory`) → 빈 씬 → 조명 · 안개 → 인테리어/거리 프리팹 → XR 리그 → 게임 흐름 → 팩 · 선반 · 계산대 → 손님 · 청소 · 도둑 → 일시정지 · 단계별 판 · 집 · 바인더 · 판매 패널 → **기억한 자리 되살림** → 저장 · 빌드 목록 등록.
- 기능마다 빌더를 나눔(`CustomerFloorBuilder`, `CleanupBuilder`, `ThiefBuilder` 등). 위치 숫자는 `ShopLayout`에 모아 런타임과 같이 씀. 빠진 연결은 `SceneSetupTests`가 잡음.
- 장점: 기능을 넣을 때마다 씬 연결을 손으로 하지 않아도 되고, 씬이 깨져도 다시 만들 수 있음. 단점: 위치를 바꾸려면 코드 숫자를 고치고 다시 빌드해야 함 → 디테일 단계에서 맵 수정 도구 · 씬 원본 방식으로 넘어감.
