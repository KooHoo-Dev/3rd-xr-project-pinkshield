# DEC-001 · 선반 팩 뒤집기: 플레이어가 놓은 방향 유지

| 항목 | 값 |
|---|---|
| 날짜 | 2026-11-16 |
| 상태 | 채택 |
| 관련 | 설계서 v1 9장 Q6, 7-6 · AI-001 |
| 포트폴리오 | |

## 문제
기획서에는 "뒷면이 위로 뒤집혀 있는 팩은 희귀 카드 확률이 높다"는 단서가 있다. 그런데 플레이어가 팩을 집었다 다시 놓으면 방향이 바뀐다. "뒤집힘"을 지금 방향으로 판정하면 플레이어가 단서를 만들거나 지울 수 있다. 선반 슬롯을 구현하기 전에 정해야 했다.

## 선택지
| | A안 (Claude 초안) | B안 (채택) |
|---|---|---|
| 방법 | 단서는 생성 시 플래그로 고정. 방향은 신경 쓰지 않음(스냅할 때 원래 자세로 돌아갈 수 있음) | 단서는 생성 시 플래그로 고정. **플레이어가 뒤집은 방향은 그대로 유지** |
| 장점 | 구현이 가장 단순함 | 모바일 포켓몬 카드 게임 팩 고르기처럼, 기억해 두고 싶은 팩을 뒤집어 "찜"하는 경험이 생김 |
| 단점 | 플레이어가 팩에 표시를 남길 방법이 없음 | 슬롯이 앞면/뒷면 두 자세로 스냅해야 함. "원래 뒤집힌 팩"과 "내가 뒤집은 팩"이 섞임 |

## 고른 것과 이유
B안. 확률은 생성 시 플래그(`Clue`)로만 판정하고, 방향(`IsFaceDown`)은 표시 상태로만 둔다. 사용자가 원한 것은 플레이어가 팩을 직접 뒤집어 기억해 두는 경험이었다. 두 상태를 분리하면 이 경험을 살리면서도 확률을 조작할 수 없다.

## 치른 대가 (Trade-off)
- 선반 소켓에 앞/뒤 판정과 자세 두 개가 필요하다(`ShelfSlotSocket`).
- 처음부터 뒤집혀 있던 팩(단서)과 플레이어가 뒤집은 팩을 구분하는 일은 플레이어의 기억에 맡긴다. 의도된 재미로 본다.
- 다음 날 선반을 다시 배치하므로 방향은 하루 안에서만 유지된다.
