# DEC-030 · 청소는 확률로 생기고, 바닥 얼룩과 대걸레를 더한다

## 문제
지금은 손님이 나갈 때마다 **무조건 1곳** 청소가 생기고, 종류는 쓰레기 · 흐트러진 팩 반반이었습니다. A9에서 손님 수를 7일차 최대 9명까지 늘리기로 해서, 그대로 두면 하루 청소가 9곳이 됩니다. 또 흐트러진 팩이 진열대와 먼 곳에 떨어질 수 있었고, 빗자루는 도둑 맞히기에만 쓰였습니다. 사용자가 청소를 다시 설계해 달라고 요청했습니다(11-19 3차).

## 선택지
| | A안 지금대로 (손님마다 1곳 · 2종) | B안 확률 생성 + 바닥 얼룩 + 대걸레 |
|---|---|---|
| 방법 | 손님이 나가면 반드시 1곳, 쓰레기 · 팩 반반 | 35% 확률 · 동시 최대 3곳 · 4명 연속 없으면 반드시, 비율 얼룩 45 · 쓰레기 35 · 팩 20, 빗자루를 대걸레로 바꾸고 문질러 지우는 얼룩 추가 |
| 장점 | 바꿀 것 없음 | 손님이 늘어도 하루 2~3곳, 대걸레가 청소 · 도둑 둘 다에 쓰임 |
| 단점 | 손님이 늘면 청소가 너무 많아짐 | 업무 종류가 하나 늘어남(DEC-014와 부딪힘), 새 코드 많음 |

## 고른 것과 이유
- **B안** (사용자 결정, Q9~Q12).
  - Q9 확률 35% · 동시 최대 3곳 · 4명 연속 없으면 다음엔 반드시 (1일차는 첫 손님 반드시 쓰레기 1곳, 이후 25%)
  - Q10 비율 얼룩 45 · 쓰레기 35 · 흐트러진 팩 20 (얼룩은 2일차부터)
  - Q11 대걸레로 도둑 치기 **유지**, 빗자루는 없앰
  - Q12 AI 보완 제안 중 4개 채택: 손님 동선 얼룩 밟으면 인내심 −3초, 손님이 나가며 쏟는 장면, 대걸레 거치대(놓으면 1초 뒤 양동이로), 첫 얼룩 튜토리얼. 전광판 종류 아이콘 · 쓰레기 넘침은 넣지 않음
- 흐트러진 팩은 진열대 앞 띠 안 · 계산대에서 보이는 자리에만 (F3)
- 창문 얼룩은 DEC-014대로 계속 뺌. 바닥 얼룩은 손님이 쏟은 것이라 손님 흐름과 이어짐.
- 사용자가 이렇게 고른 이유: (채우기)

## 치른 대가 (Trade-off)
- 업무 종류가 다시 3종(쓰레기 · 팩 · 얼룩)이 됨. DEC-014에서 "영업 중 할 일이 너무 많아지지 않게" 2종으로 줄였던 것을, 생성 수를 확률로 줄이는 대신 종류를 늘리는 쪽으로 바꿈.
- 에셋에 대걸레가 없어 빗자루에 코드로 모양을 덧붙임(`MopStation`). 클래스 이름 `Broom` · 소리 칸 `BroomHit`은 그대로라 이름과 모양이 다름.
- 청소 생성 시점이 "손님이 나간 뒤"에서 "나가기 시작할 때"로 바뀜(쏟는 장면 때문).
- 청소 확률 값은 아직 `CampaignConfig.asset`에 없고 코드 기본값을 씀.
