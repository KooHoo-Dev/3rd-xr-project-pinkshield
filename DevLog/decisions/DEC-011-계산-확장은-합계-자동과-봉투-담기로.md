# DEC-011 · 계산 확장은 "합계 자동 + 봉투 담기"로, 가격 입력은 나중에

## 문제
Quest 기기 테스트 후 사용자 피드백: 손님이 카드팩 하나만 사서 계산이 단조롭다 → 피규어 · 카드팩 상자도 사고, 바코드를 다 찍으면 포스기에서 **가격을 입력**하고 결제.
보완안으로 "가격 입력이 너무 복잡하면 산 물건을 열린 종이봉투에 담아 준다"를 함께 냄.
Claude가 기존 계산 코드(`CustomerDirector` 안의 바코드 → 결제 버튼)를 읽고 설계서를 쓴 뒤 결정 항목 6개(K1~K6)를 제안했고, 사용자가 **모두 추천안으로** 정함.

## 선택지
| 항목 | 검토한 안 | 고른 것 |
|---|---|---|
| K1 결제 방식 | A 가격 직접 입력(키패드) / B 합계 자동 + 봉투 담기 / C 받은 돈 · 거스름돈 입력 | **B 먼저, A는 나중에 후반 일차 난이도 · 옵션** |
| K2 순서 | 찍기 → 봉투 → 결제 / 찍기 → 결제 → 봉투 | 찍기 → 봉투 → 결제 |
| K3 계산 보상 | a 손님 팁 / b 사장님 평가 → 알바비 가감 / c 실수 감점만 | b (청소 보너스 · 감점과 같은 방식) |
| K4 피규어 모양 | 아크릴 스탠드(카드 캐릭터 그림 재사용) / 슬라임 피규어 메시 | 아크릴 스탠드 |
| K5 장바구니 개수 | 1~4개, 후반 일차에 늘어남 | 분포는 SO 값(`ShopItemConfig`)으로 테스트하며 조정 |
| K6 인내 시간 | 그대로 / 물건 수에 비례 | 물건 2개째부터 한 개당 +10초 |

## 고른 것과 이유
설계서에 적은 Claude의 근거 (사용자는 추천안을 그대로 채택):
- VR 키패드는 누르기가 느리고 잘못 눌리기 쉬움(시연 피드백 C2에서 버튼 간격 문제를 이미 겪음). 화면 숫자를 다시 치는 일이라 손만 바쁘고 재미는 적음.
- 봉투 담기는 **물건을 집고 넣는 손동작**이라 VR에 맞고, 물건이 여러 개일수록 자연스럽게 일이 늘어남.
- 키패드는 B 위에 그대로 얹을 수 있게 설계 → B를 먼저 만들어도 버리는 코드가 없음.
- 지금은 가게 재고를 팔아도 플레이어 돈이 그대로라, 보상이 없으면 계산이 "귀찮은 일"만 됨 → 이미 있는 청소 보너스 · 감점 자리에 계산 평가를 더함.
- 외부 에셋에 피규어 모델이 없음 → 이미 있는 슬라임 누끼 그림으로 50종을 새 에셋 없이 만듦 (DEC-010 D5 "아크릴 스탠드 직접 제작"과 같은 방향).

## 치른 대가 (Trade-off)
- 사용자 원안의 "가격 입력" 손맛(숫자 실수 · 긴장)은 당장은 없음 → 4장 실수 처리(안 찍은 물건은 봉투가 튕김)로 일부 보완, A안은 나중 과제로 남김.
- 봉투 담기를 하려면 계산대 물건을 잡을 수 있게 바꿔야 함(지금은 콜라이더만) → 4단계 작업이 커짐.
- 계산 코드를 `CheckoutCounter`로 분리하는 리팩터링이 먼저 필요했음 (1단계).
